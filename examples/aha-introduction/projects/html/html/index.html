Aha / An introduction

Aha: two skills.
From evidence to explanation.

Aha is a pair of portable skills: research establishes what happens, why, and how far the evidence reaches; explain turns that supported account into the medium you request.

The host coordinates the work

aha-research

Investigate the question. Keep the answer, sources, reasoning, and limitations together in a Research Dossier—a reusable evidence record.

aha-explain

Use that evidence to author the requested visual explanation. Choose a composition that makes the mechanism visible, rather than merely restyling a report.

Two skills, not automatic dispatch. The host decides when to research, reuse a Dossier, and author a medium. Research can also be the final deliverable.

01

Greenland: map footprint is not spherical area

A useful explanation first separates what changes from what stays fixed.

On a spherical Mercator map, enlargement grows at high latitudes. Longitude spacing stays fixed on the map even though meridians converge on the sphere; preserving local angles requires matching north–south enlargement.

Now apply the same rigid spherical rotation to every point of Greenland’s boundary. Its spherical area stays the same, but moving it toward lower latitudes changes its apparent footprint on the fixed projection. This is not a two-dimensional shrink operation.

Scope matters. This is a generalized spherical model with polar cropping, not every map or a precision area measurement. Relocation is hypothetical—not real continental motion. There is no single uniform whole-country scale factor.

Inherited sources: PROJ’s Mercator description and Natural Earth 5.1.2 generalized boundaries (data terms). No new map calculation is performed here.

02

CPython: the object is not its UTF-8 encoding

Start with 100,000 ASCII characters. Concatenate U+1F600. The new string and its encoded payload answer different size questions.

In this CPython 3.11.15 example, the resulting compact str uses one code-point slot width throughout. Because U+1F600 exceeds U+FFFF, the new object needs four-byte slots, including its ASCII prefix. The original immutable str is untouched. UTF-8, by contrast, keeps each ASCII character at one byte and adds four bytes for U+1F600.

Every code-point slot in the new result is 4 bytes. These are schematic slots, not 100,001 drawn cells and not a memory-address diagram. Display widths are not numerically proportional to byte counts.

The earlier ASCII-only object still has its original representation. Concatenation uses the operands’ representation ranges; this is not a claim that every concatenation scans all code points.

Variable-length encoding, not uniform slots

AA…U+1F600

The 100,000-character ASCII prefix stays at 100,000 bytes. U+1F600 adds 4 bytes, giving a 100,004-byte UTF-8 payload. The boxes are schematic; display widths are not numerically proportional to byte counts.

These are encoded payload bytes, not the memory occupied by a Python bytes object, a process, or a measured file.

Docker: an absent path can leave retained bytes

Separate the merged filesystem view from the immutable image layers beneath it.

In an ordinary unsquashed image, a first RUN records a new file’s content in a layer. A later RUN can record a whiteout—a deletion entry that hides the lower path in the merged view. It does not rewrite the earlier layer blob.

Why one RUN can differ

A NEW temporary file created and deleted within one RUN is absent at both endpoints. Its payload is therefore absent from that path’s resulting diff. This does not make the entire layer empty or reclaim a preexisting base-layer file.

Choose the medium for the explanation

The evidence stays bounded; the composition changes. These are supported choices, not a claim that every example has all four completed outputs.

HTML · explore a distinction

Let readers compare representations or inspect a mechanism at their own pace, with the sources close at hand.

PNG · keep the essential contrast

Compose a self-contained visual summary for its actual reading size—not a miniature article.

Native PPTX · explain in sequence

Use editable text and shapes to support a presented argument, with an intentional purpose for each slide.

Video · make change visible

Coordinate mechanism changes with narration and captions, rather than relying on page transitions alone.

The common thread is not a visual template. It is the relationship between supported evidence, a visible mechanism, and a clearly stated limit. That is the editorial aim of these examples—not a measured learning outcome.

01

格陵兰：地图上的大小，不等于球面面积

讲清一个机制，先区分什么变了、什么没有变。

球面墨卡托投影在高纬度的放大更明显。球面上的经线逐渐汇聚，地图却保持经线等距；为了保持局部角度，南北方向也必须相应放大。

假设给格陵兰边界的每一个点施加同一个球面刚性旋转。它的球面面积不变，但移向低纬度后，在固定投影上的轮廓大小会改变。这不是把二维图形直接缩小。

适用范围不能省略。这里使用概化的球面模型，并裁去极区；不能推及所有地图，也不是精密面积测量。搬移是假设的几何操作，不是真实大陆运动；整个格陵兰也不存在一个统一的放大倍数。

沿用来源：PROJ 的墨卡托投影说明及 Natural Earth 5.1.2 概化边界（数据使用条款）。本页没有执行新的地图计算。

02

CPython：字符串对象，不等于 UTF-8 编码

从 100,000 个 ASCII 字符开始，再拼接 U+1F600。新字符串对象与它的编码数据，回答的是两种不同的大小问题。

在这个 CPython 3.11.15 示例中，拼接所得的紧凑型 str 为所有码点采用统一槽宽。U+1F600 超过 U+FFFF，因此新对象需要四字节槽，ASCII 前缀也包括在内。原来的不可变 str 没有被修改。UTF-8 则不同：ASCII 字符仍各占一字节，U+1F600 只增加四字节。

新结果中的码点槽，宽度一致

AA…U+1F600

新结果中的每个码点槽都是四字节。上图只是槽位示意，没有画出全部 100,001 个槽，也不是内存地址图。显示宽度不与字节数成比例。

原来的 ASCII 字符串仍保留原有表示。拼接会利用操作数的表示范围，这不意味着每次拼接都会扫描全部码点。

编码长度可变，不采用统一槽宽

AA…U+1F600

100,000 个 ASCII 字符仍占 100,000 字节。U+1F600 增加四字节，因此 UTF-8 编码数据合计 100,004 字节。方框仅作示意，显示宽度不与字节数成比例。

这里数的是编码数据的字节，不是 Python bytes 对象的内存占用、进程内存或实测文件大小。

Docker：路径不见了，旧层的字节还在

把合并后的文件系统视图，与下方不可变的镜像层分开看。

在普通、未压平的镜像中，第一次 RUN 把新文件内容记录到一层里。后一次 RUN 可以记录 whiteout（删除标记），使较低层的路径在合并视图中不可见，但不会重写较早的层数据。

按钮只切换既有讲解中的示意状态，不会执行 Docker，也不会测量存储。

为什么同一次 RUN 可能不同？

如果新建临时文件在同一次 RUN 中创建又删除，那么操作前后都没有这个文件。因此，该路径的最终差异中不会留下它的内容。这不代表整个层为空，也不会回收基础层中原有文件的数据。

100 MB 指假设的 100,000,000 字节未压缩内容，不是压缩镜像大小、传输量、缓存用量或物理存储量。本次没有运行 Docker 构建。沿用来源：固定版本的 OCI 层规范与 Moby 27.5.1。既有代码追踪仅涉及选定的经典／回退路径，不涵盖所有 BuildKit 后端，也不讲解运行中容器的可写层。

04

依据讲解任务，选择媒介

证据的边界不变，表达方式可以不同。以下是支持的选择，并不意味着每个案例都已经交付四种格式。

HTML · 自主比较

让读者按自己的节奏比较表示方式、查看机制，随时查阅相邻的来源。

PNG · 留住关键区别

按实际阅读尺寸独立构图，形成自足的视觉摘要，而不是把文章缩成小图。

原生 PPTX · 逐步讲述

用可编辑的文字与形状组织演示，让每一页都承担明确的讲解任务。

视频 · 展示变化

让机制的变化与旁白、字幕配合，而不只是为页面加上转场。

贯穿这些媒介的不是固定模板，而是有依据的结论、看得见的机制与说得清的限制之间的关系。这是这些案例的编辑目标，不是经过测量的学习效果。
