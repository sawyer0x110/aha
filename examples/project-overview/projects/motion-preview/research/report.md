# Aha：把难懂的问题调研清楚，再做成可用的讲解

## 面向新用户的直接答案
Aha 是给 Agent 使用的两个技能：先深入研究一个问题，再把有证据的解释做成用户选定的作品。用户提供问题或材料、目标读者及所需格式；Agent 调研和创作，运行时负责检查、打包与渲染。成品可以是能交互的网页、适合一眼阅读的图、可修改的幻灯片，或有旁白的动态视频。它不是只写一段回答，也不是保证正确的一键转换器。[c-purpose, c-formats, c-qa]

## 先看作品，再讲实现
仓库已有两个非本项目题材的真实 HTML 作品。降噪耳机案例以“飞机轰鸣变轻了，为什么人声还在？”为问题，并提供一个明确标为理想模型的相位滑块。Git merge 案例以“为什么合并会带回已撤销的修改？”为问题，让读者对照三个预先记录的合并案例。它们说明具体输出可以包含图解和受限定的交互；本次展示不是重新完成声学实测、实时 Git 实验或真人理解测试。[c-examples]

示例截图只是对已有作品的展示，原网页才有交互。新介绍不能把截图做成假的实时实验，也不能声称这些题材已经生成了其他三种格式。图片、PPTX 和视频的形态可用当前项目自己的实际成品补足，并明确区分来源。

## 本轮讲解的主线与取舍
先点明 Aha 是什么，再给一个问题和实际输出，接着说明“调研问题—为受众设计所选媒介—交付作品与可编辑源”，最后总结何时使用。两种 Skill 的职责保留；哈希、源码重建和执行权限降为开发/制作补充资料，不再让新用户先理解协议才能理解产品。研究身份、授权和限制仍实际遵守，不能因弱化展示而省略执行。

本轮是在原有固定源码研究上补充一个作品目录来源，核心实现结论没有更改。HTML/video 绑定这个新快照；先前 PNG/PPTX 仍可保留原快照身份。旧快照不被覆盖。

## 直接结论
Aha 不是“输入一句话就自动证明事实并生成所有媒体”的引擎，而是两个可移植 Skill 加一套本地运行时。宿主 Agent 负责调查、推理和内容设计；运行时负责协议、身份、资源打包与渲染。两者分工让同一组有来源的结论可以被重新组织为交互网页、一图流、原生幻灯片和动态讲解视频，而不必让研究报告服从某种固定版式。[e-readme, e-research-skill, e-explain-skill]

## 范围、读者与方法
本报告为第一次接触项目的使用者和贡献者介绍当前仓库。调研固定在 sawyer0x110/aha 提交 a013ea795312eab9ae2e4224998a1314eea8f718，runtime 0.3.0、研究/作品协议 1.0.0；日期 2026-09-15。读取当前工作树并用固定提交片段复核。预算为一轮定位、一次实现/测试反查和一次逐主张语义回查，不做外网搜索、生产性能实验或全库安全审计。

问题树先回答 q-purpose（项目解决什么），再回答 q-identity（研究怎样与作品绑定），由此展开 q-formats（为何要分别创作）与 q-permission（执行和声音外发的界线），最后回答 q-distribution（如何携带给宿主）。q-live 单独保留，避免从文档及测试代码推断线上服务、真实宿主和真人理解已经通过。

## 从问题到作品，数据怎样走
用户只要报告时，aha-research 完成问题分解、取证、反证与综合，交付独立档案。用户要视觉作品时，aha-explain 直接使用共享研究流程，不要求宿主自动转发给另一个 Skill。[e-research-skill, e-explain-skill]

Research Dossier 是保存一份研究的目录：research.json 保存主张、来源、读取日志、缺口及完整报告；report.md 提供直接阅读的同一报告；manifest.json 记录协议、研究 ID 和派生的内容哈希。严格构建会检查完整性和引用，验证时重算身份。这里的哈希相当于内容的指纹：能发现内容是否改变，不能说明一句结论是否成立。[e-dossier, e-architecture]

每份媒介项目持有研究副本，并在 artifact.json 中声明一种格式、作品入口、语言、尺寸、研究哈希与主张覆盖。每条主张必须出现在覆盖表，或以明确理由省略；草稿标记未移除时拒绝作为已编写作品。这是防止漏交与身份混淆的机械门槛，不会替作者证明图中的箭头或文字真的表达了所映射的主张。[e-project]

HTML、PNG、PPTX 交付收据记录 researchHash、sourceHash、outputHash。若作者修改源码，旧输出仍能作为历史版本保留，但不能把旧收据说成新源码的渲染结果。研究改动则建立新的研究快照，再有意识地重新绑定作品。视频另有绑定源码的计划和音频身份链，因此只改画面也可能使旧音频的绑定失效。[e-render, e-plan, e-architecture]

## 四种格式，共用事实而非版式
HTML 适合读者自己探索关系：本地资源内嵌，可有 SVG、Mermaid 和离线控件。PNG 需要为固定视口重新构图，不是把长文章缩小。PPTX 由作者函数添加原生文字、形状、表格或图表，运行时负责写文件，不接受只有整页截图的幻灯片。视频由作者按帧回调设置画面状态，实际音频确定帧数，并输出烧录字幕及 SRT；不是自动把任意脚本变成动画。[e-architecture]

新 HTML 默认双语、先英语；其他格式默认英语。中文提问本身不更改作品语言默认值，明确 --language zh 才选择中文。Agent 编写译文，本地切换不调用翻译服务，不改研究快照。这是语言与事实身份解耦，而不是自动翻译能力。[e-language, e-project]

## 权限为什么分两层
render-html 打包时不执行作者脚本，所以不需要为了打包而开放本地代码执行。图片捕获、浏览器检查、视频画面和 PPTX 作者函数会执行代码，需先审阅并取得明确本地授权。Node 模块拥有宿主进程权限；超时和 --allow-code 都不是 OS 沙箱。[e-render, e-execution]

在线 Edge TTS 还会向提供方发送旁白，因此必须另行批准当前完整文本、提供方、声线、语速、外发范围和 planHash。源码、旁白或声音参数改变时，原批准不能通过手改哈希移植过来。检查实现中的 VIDEO_SOURCE_MISMATCH 与精确 planHash 比较支持这个拒绝路径，但不证明本机已经成功联网合成。[e-plan, e-execution]

## 如何使用与贡献
接收方需要完整构建/发布包，不是直接复制源码 skills 目录。构建脚本输出恰好 aha-research 和 aha-explain 两套 Skill，各带 CLI、Schema、渐进参考、Mermaid、Playwright 和第三方声明；浏览器、Python、FFmpeg 不随包分发。开发者可从 src/research、src/artifacts、src/media 追踪研究、作品和视频链，tests 中的断言验证对应程序行为，evals 另行处理技能效果研究。[e-build, e-architecture]

## 反证与语义回查
最初可能将“四种格式”理解成统一自动生成命令。检查 FORMATS 与单项目 format 字段后，将结论收窄为分别初始化、分别编写、分别验收。另一种误读是“检查通过等于事实正确”；checkArtifact 的声明与收据 verification 明确反对这一推断。测试源码也分别断言覆盖缺失、草稿、语言默认和源码变化，不对真人理解做断言。[e-project, e-render, e-tests]

逐主张回查结果：c-purpose、c-dossier、c-formats、c-identity、c-permission、c-video、c-language、c-distribution、c-qa 均限制为当前实现或契约的描述，没有推断性能、线上可用率或效果增益。没有将未运行的测试称为通过。制作期间实际生成与检查的结果放在案例 QA，不倒灌为固定研究快照的事实。

## 未解决与停止理由
本地 doctor 已观察到浏览器、FFmpeg、ffprobe 可用，而选中的 Python 缺少可用的指定 Edge TTS 环境；这是制作阶段诊断，不证明远程服务可用。真实宿主发现、正式 Release、桌面 PowerPoint 跨机兼容、在线语音服务条款适用性及真人理解效果仍需各自独立观察。本报告不访问私人材料，也不外发仓库代码。

核心项目介绍已由入口、实现和测试断言交叉支撑；继续查未授权线上环境不会改善这些有限结论，故以明确缺口停止。后续作品会复用此快照并分别记录格式、执行与视觉验收。
