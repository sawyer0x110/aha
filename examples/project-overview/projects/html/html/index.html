AHA / RESEARCH + VISUAL EXPLANATION

Aha: research a difficult question.
Explain it visually.

Aha is a pair of agent skills for turning questions and source material into a researched explanation people can read, explore or present.

You bring four things

A question, any starting material, your audience, and the output you need.

For example: “Explain headphone noise cancellation to curious non-specialists as an interactive HTML page.”

START WITH A QUESTION PEOPLE HAVE

Why does headphone rumble fade while voices remain?

A visual explanation can put the incoming sound, the headphone’s response and their combined pressure side by side. The existing ANC example lets readers change a phase mismatch in an idealized model.

02 / FROM QUESTION TO SOMETHING USEFUL

Investigate first. Design for the reader.

  1. 01 / INVESTIGATE

    Find what supports the answer

    Read sources, compare contradictory evidence and record gaps. Keep the claims and their evidence in a research snapshot so the explanation has something to build on.

  2. 02 / DESIGN

    Choose what the audience needs to see

    Turn the supported reasoning into a comparison, diagram or sequence. A reader exploring alternatives needs a different composition from a team watching a short briefing.

  3. 03 / DELIVER

    Keep both the work and the result

    Deliver editable source plus the usable output for the requested medium. Review the actual result so the explanation, controls and layout can be checked together.

Two skills, two entry points. Use aha-research when you want a research report. Use aha-explain when you want a visual artifact; it can use the shared research workflow itself.

Sources: Skill entry points and research and artifact architecture.

Use Aha when the answer needs a bridge

You have a difficult concept, scattered evidence or code behavior to explain—and an audience that needs more than a conclusion. Bring the question and the reader; choose a report or a visual artifact they can actually use.

Implementation, provenance and review limits

Research and revision identity

The research snapshot’s manifest.json, research.json and report.md preserve research independently of any medium. Each project declares claim coverage or omissions. HTML, PNG and PPTX receipts link research, source and output hashes. Changed source needs a new output and receipt; matching hashes identify revisions, not factual quality.

Execution and narration approval

HTML packaging does not execute author scripts. Browser checks, image capture, video frames and native PPTX code need explicit local-execution approval. --allow-code is not a sandbox. Edge TTS separately requires approval of the current complete narration plan, provider, voice, rate and disclosure scope.

Video has its own timing work

The narration plan binds to the research and source. Authored frame states and measured audio durations drive the sequence and captions. A changed plan invalidates stale approval. Successful encoding does not replace watching and listening to the result.

Language is authored, not inferred

New HTML defaults to English and Chinese, initially English. PNG, PPTX and video default to English, with explicit Chinese available. The agent writes the translation; changing artifact language does not change the bound research.

Installation and dependencies

Install a built Skill package with its CLI, schemas, references and local libraries—not the source skills directory. Browsers and media tools are separate dependencies; prepare those needed for the chosen step.

What this introduction does not establish

Source checks, factual review, language review and actual output inspection are distinct. These examples do not establish learner comprehension, host discovery or online voice availability. This page uses the host’s Clawpilot theme; it is not an Aha-only quality evaluation.

Technical references: render receipts · execution permissions · language · installation · artifact QA.

AHA / 研究 + 视觉讲解

Aha：研究一个难题，
用视觉讲清楚。

Aha 是一组包含两个 Skill 的 Agent 技能：把问题和原始材料，变成有研究依据、可供阅读、探索或演示的讲解。

你带来四样东西

想弄清的问题、已有材料、讲给谁听，以及需要什么形式的成品。

例如：“给好奇的非专业读者解释耳机主动降噪，做成可交互的 HTML 页面。”

从读者真的会问的问题开始

戴上降噪耳机，为什么轰鸣变轻了，人声还在？

视觉讲解可以把传入声、耳机发出的声音，以及两者叠加后的声压放在一起比较。现有 ANC 示例让读者在理想模型中改变相位偏差，观察变化。

02 / 从问题到可用的作品

先调查，再为读者设计讲法。

  1. 01 / 调查

    找出答案依据什么

    阅读来源，对照相互矛盾的证据，记录尚未解决的缺口。把主张及其证据保存为研究快照，给后续讲解提供依据。

  2. 02 / 设计

    决定读者需要看见什么

    把有依据的推理组织成比较、图解或过程。想自己探索不同情况的读者，与听简短汇报的团队，需要不同的构图和顺序。

  3. 03 / 交付

    留下源码，也交付成品

    交付所选媒介的可编辑源码与可用成品。检查实际输出，让内容、控件和版式一起接受审阅。

两个技能，两个入口。想要研究报告，用 aha-research；想要视觉作品，用 aha-explain，它可以直接使用共享研究流程。

来源：Skill 入口与研究和作品架构。

不只要给结论，还要把道理讲通时，用 Aha。

你需要解释一个难懂的概念、一组零散证据，或一段代码的行为，而读者需要知道“为什么”。带上问题，说明讲给谁听，再选择他们用得上的研究报告或视觉作品。

展开实现细节、来源与审阅边界

研究和版本身份

研究快照的 manifest.json、research.json 与 report.md 独立于媒介保存研究。每个作品项目声明主张的覆盖或省略。HTML、PNG 与 PPTX 的收据关联研究、源码和输出哈希。源码改变后，需要新输出和收据；哈希匹配只能识别版本，不能证明内容正确。

执行与旁白批准

HTML 打包不执行作者脚本。浏览器检查、图片捕获、视频画面和原生 PPTX 代码都需要明确的本地执行批准。--allow-code 不是沙箱。Edge TTS 另需批准当前完整旁白计划、提供方、声线、语速与外发范围。

视频还要单独安排时间

旁白计划绑定研究与源码。编写的逐帧状态与实测音频时长共同决定画面顺序和字幕。计划改变后，旧批准失效。编码成功不能代替实际观看和听审。

语言由作者选择，不靠猜测

新 HTML 默认中英双语，先显示英语。PNG、PPTX 和视频默认英语，也可明确选择中文。译文由 Agent 编写；改变作品语言不会改变绑定的研究。

安装与依赖

安装带有 CLI、Schema、参考资料和本地库的构建后 Skill 包，而不是源码中的 skills 目录。浏览器和媒体工具是额外依赖，按当前步骤准备。

本介绍不能证明什么

源码检查、事实审阅、语言审阅和实际成品检查各不相同。这些示例不证明真人理解、宿主发现技能或在线语音可用性。本页使用宿主的 Clawpilot 主题，不是 Aha 单独作用的质量评估。
