# Aha Skills 重构方案：研究驱动的自由创作

> 日期：2026-09-14 · 依据：[PRD v0.3](PRD.md) 与实现基线 `9db6173`
>
> 本文保留架构决策与实施路线，不是命令手册。新版 runtime 0.3.0 只保留 `aha-research`、`aha-explain`，实际协议、命令和限制见 [README](../README.md)。下文目录示意与里程碑用于说明设计，不能替代运行时 Schema 或实际作品验收。

## 1. 核心判断

**需要改变主干架构，而不只是放宽几处 maxItems 或补几个提示词。**

重构前的系统是“Agent 填写严格 Draft → 固定 renderer 生成多格式”。对受控实验有效，但让不同主题自由排版时，研究、叙事和版式都被模型／场景／slides 结构牵制。

新主干应是：

**Agent 深入研究 → 保存独立研究档案 → 按媒介编写作品源 → 本地工具渲染与检查。**

研究事实是共用底座，作品源是视觉表达的权威来源。工具层尽量薄，但身份、权限、资源、错误与实际检查不能薄。

### 从参考项目学什么

| 参考 | 直接启发 | 不应照搬 |
| --- | --- | --- |
| visual-explainer | 默认可自由编写完整 HTML；按内容读取布局／图形参考；图表达机制；可选 quick 路径而非唯一入口 | 将全部作品重新锁进 quick Schema；要求所有图同一种布局 |
| anything2explainer | 研究、旁白、真实音频、分镜、镜头创作、小样、QC 构成生产流程；参考作品给出质量标尺 | 受非商业许可限制的实现／提示词／素材；一开始就搭长片、多 Agent 大规模编排 |
| 现有 Aha | 研究协议、身份与引用、原生 PPTX、Edge TTS 审批、离线打包和明确错误 | 强制引擎选择、固定教学状态、所有格式共用 slides、静态卡片等于动态视频 |

上游对照版本与采用边界见 [参考记录](REFERENCE-ADOPTION.md)。外部项目的方法不是已集成能力，也不能证明 Aha 成品质量。

## 2. 确定的 Skill 划分：只保留两个

`aha-research` 负责复杂调研，`aha-explain` 负责生成。只有这两个发布入口，不保留 Lab／Story 别名，也不按格式增加 Skill；两者随独立运行时一起发布，不是空入口。

| 入口 | 触发与职责 | 交付 |
| --- | --- | --- |
| `aha-research` | 研究 topic、开放问题、代码库／diff；规划、取证、补查、综合、反向核对 | 研究报告、Dossier、来源／检索／缺口记录 |
| `aha-explain` | 基于研究制作 HTML、一图流、PPTX、视频；也接受从 topic 开始的完整请求 | 独立作品源、用户指定成品、资源与 QA 记录 |

`aha-explain` 从 topic 开始时先走共享的研究工作法，不维护另一套简化调查，也不依赖宿主能自动调用其他 Skill。已有研究可读取后检查时效与覆盖，仅补缺口。用户只要研究时不启动创作；只要某一种格式时不生成其他格式。

HTML／image／PPTX／video 是 `aha-explain` 的按需工作流与工具模块，不是四个独立 Skill。共享研究参考和工具库不作为第三个可发现的 Skill 发布。

### 删除范围与保留范围

| 删除／退出主干 | 保留／提取 |
| --- | --- |
| `skills/aha-lab`、`skills/aha-story` 及只服务它们的工作流 | `aha-research`、新 `aha-explain` 与按需共享参考 |
| 固定实验引擎作为入口、强制教学题、探索导入导出作为主线 | 来源定位、研究台账、版本身份、事实核对 |
| 不再被新路径使用的 Pack／场景／固定布局模块及其依赖 | 可复用的 HTML／SVG、原生 PPTX、截图和排版工具 |
| 旧入口注册、旧命令文档、废弃 fixtures 与契约测试 | Edge TTS、音频时长、字幕、授权、错误报告和通用回归 |
| 与最终方案无关的暂停 Studio 代码及过期设计材料 | 经核实可用的构建／检查辅助，不将整套 Studio 原样启用 |

按调用与依赖关系清理，不因为文件名含 lab／story 就删除其中可复用逻辑。先提取新路径需要的工具，移除旧调用，再删无用代码、依赖、测试和文档；不是删除失败测试以宣布通过。

不建立永久旧版兼容层。仓库代码与发布清单可以清理，但用户既有作品、研究材料和外部安装目录不自动删除；安装器遇到旧入口应明确报告，由用户授权替换，不静默残留或清空其他内容。

## 3. 研究层：脱离呈现协议

### 3.1 已实现的研究档案

一个可复制的三文件目录，协议版本为 `1.0.0`：

```text
topic.research/
  manifest.json
  research.json
  report.md
```

| 文件／对象 | 最小职责 |
| --- | --- |
| `manifest.json` | 协议版本、研究 ID、规范化内容哈希 |
| `research.json` | 问题、类型、语言、状态、报告、`subquestions`、`claims`、`evidence`、`researchLog`、`gaps` 与 `stopReason` |
| `report.md` | 与研究数据中报告严格一致的可读版本；不必预写幻灯片 |

子问题是扁平数组；复杂问题树、受众、范围与预算写入报告，不添加 Schema 未声明的字段。来源记录保留定位、版本、读取记录与必要内容；代码证据额外绑定捕获文本及其 SHA256。研究档案当前不提供任意附件目录，作品素材保存在作品源中并说明来源。

不包含必填 `modelSpec`、`scenarios`、`traces`、`teaching` 或 `narrative.slides`。研究 Schema 只约束必要的证据结构，不限制题材和媒介。

内部允许迭代写作；交付快照有明确身份。后续补证生成新版本，旧作品仍指向原版本，不能偷偷替换事实底座。

### 3.2 深入调研的执行循环

1. 建立问题树与证据需求，确定一个可交付的回答范围。
2. 开放问题读一手来源与方法；代码问题追实际入口、关系与失败路径。
3. 更新 Claim、反证、数值口径与缺口；区分来源断言与自己的推理。
4. 根据缺口定向补查，而不是按关键词无边界搜集资料。
5. 反向核对关键结论是否真正由相应版本与上下文支持。
6. 写综合答案，解释冲突与未知，记录停止理由。

代码与公开研究共用台账但不混用证据标准。公开文档不能证明本地 dirty 代码已实现某行为；源码阅读也不证明线上实际性能。

深度预设可提供 quick / standard / deep，但它们是预算与覆盖策略，不是准确性等级。优先完善 standard/deep；达到预算时交代未答问题，不静默降级为摘要。

### 3.3 校验与事实核对分层

- 程序检查：结构、唯一 ID、引用、来源版本、资产路径、单位元数据与覆盖。
- Agent／人工语义复核：来源是否真的支持结论、反证是否遗漏、推理是否成立。
- 可执行核对：仅对已授权且可隔离的计算／代码任务运行，记录具体环境和输入；不是所有研究必经阶段。

新增成品级 fact-check 工作流：从正文、图关系、数字与旁白抽取关键断言，回查研究，再按必要性重读源。报告“支持／应修正／不足／不可核查”，不能靠映射 ID 自动声明正确。

## 4. 创作层：作品源优先，结构化元数据辅助

### 4.1 已实现的作品目录

```text
topic.work/
  artifact.json
  research/
    manifest.json
    research.json
    report.md
  html/
    index.html
  pptx/
    main.mjs
```

每个媒介单独初始化一个项目：HTML／image／video 使用 `html/index.html`，PPTX 使用 `pptx/main.mjs`，不会同时创建两种入口。可在项目内增加本地素材与设计笔记；不引入必须跨媒介共享的巨大场景图。

`artifact.json` 保存 format、研究身份、入口、尺寸、草稿／已编写状态，以及 `coverage` 和 `omissions`；不保存固定页面 DSL。项目源与素材纳入源哈希；顶层 `research`、`dist`、`qa` 不计入源哈希，研究另有身份。实际发布目标必须在作品目录外。

作品另有可选 `language` 枚举 `en`／`zh`／`bilingual`。新初始化项目总写入该字段，但为兼容旧元数据不将其设为必填：缺失时保留旧单源行为，不自动转成双语，视频声线有效回退为英语。语言只作用于作品，绝不翻译／修改绑定的研究档案。

`coverage` 将作者指定的段落／图／幻灯片／镜头标识映射到 Claim，`omissions` 为未覆盖主张记录理由；没有额外必填 `provenance.json`。面向读者保留自然来源入口，不显示内部 ID；映射检查不能代替关键断言语义核查。

作品源可以是：

- 完整 HTML/CSS/JS、Mermaid 源与 SVG。
- 一图流的 HTML/SVG 排版源。
- PptxGenJS 构建代码和素材。
- 视频的叙事、旁白、分镜与动画场景代码。

源文本允许自由排版；严格结构用于元数据、数据表和媒介边界。普通来源字符串仍需转义，不从研究正文拼出可执行脚本。

### 4.2 内容和设计的共同流程

先做 coverage plan：必须讲的主张、机制、案例、限制，以及可省略的细节。再做 design plan：主结论、阅读路径、图形关系、字体／色彩角色、密度与交互。

两者之间增加简短的解释性编辑：检查对象指代、术语、条件和推理连接，先读文字再配合图形验证。双语先分别审读自然度和解释完整性，再交叉核对事实，不把英文短句逐字移植成中文。以渐进式参考 `explanation-writing.md` 承载方法，不增加 Skill 或必填协议字段。最终 QA 分开记录事实支持、解释清晰度、语言质量、视觉／编辑可用性与运行完整性。

模板是起点，模式库按需加载。主题需要新关系时允许编写局部图形和交互，不要求先修改库或放宽所有作品约束。频繁重复的局部实现再抽成共享组件。

“不手改最终 HTML”改为更精确的原则：**修改可追溯的创作源，再发布新快照；不能只改构建缓存或成品而留下不可复现状态。** 对直接编写的 HTML，源文件就是可编辑权威文件，不强制再包一层 JSON。

### 4.3 自由为默认，模板只是工具

自由创作为默认；可复用模板只是 `aha-explain` 内部的创作起点，不为保留旧产品而维护平行管线。不适合模板时编写作品源，不把所有主题塞进 `evidence` 后生成同款页面。

新增渐进式参考 `format-selection.md`、`visual-design.md` 与 `design-themes.md`：明确请求优先，未指定媒介的视觉解释默认 HTML 并说明；只调研／文字问答除外，不自动全格式生成。重大用途／预算歧义才询问，CLI 仍显式选择一个格式，多格式分别建立项目。

主题配方提供具体配色、字体、构图和跨媒介指导，用户／项目品牌优先，Clawpilot 是兼容基线而非唯一美学。不添加主题枚举、模板 DSL 或新的 Skill。HTML 打包先注入缺省样式，作者 CSS 随后生效；保留 `--cp-*` 角色供 Mermaid／控件使用，作者可重定义相关浅／深色变量和正文样式。Mermaid 使用正文计算字体。初始模式按有效 `scoutTheme` 参数、作者 `data-theme`、系统偏好依次决定；不提供自动主题切换 UI。

配方是原创方法指导，不是已交付的优秀作品集。产品验收仍需真实主题的跨媒介作品、实际页面／镜头检查与缺陷修复记录；仓库中的结构／浏览器回归和人工评测提示不得冒充该验收。

retry / compound 不再作为必须保留的内置引擎。具体作品需要计算时，复用经验证的独立函数或编写有依据的计算模块，并单独验证。预录步骤、图形导航和参数模拟使用不同说明，不保留独立 Lab 产品线。

## 5. 按媒介重新实现

### 5.0 语言选择与作者责任

初始化语法为 `explain-init <research-directory> <html|image|pptx|video> <new-project-directory> [--language en|zh|bilingual]`。新 HTML 默认 `bilingual`，英语初始可见并内置 English/中文按钮；新 image／pptx／video 默认 `en`，即使提问或研究为中文也不推断中文输出。用户明确要求中文时使用 `zh`；HTML 允许显式单语 `en`／`zh`，非 HTML 拒绝 `bilingual`。

由 Agent 编写目标语言内容，Aha 打包作者译文，不联网自动翻译。标题、正文、图表、控件／图注、无障碍标签、限制和引用措辞须准确翻译，保留证据、Claim ID、单位、否定、条件和不确定性。新 scaffold 仍为草稿；两分支非空等结构检查不是翻译认证。完整契约见 [语言参考](../skills/aha-explain/references/language.md)。

### 5.1 HTML：第一条新主路径

- Agent 直接写完整页面，参考按 architecture / sequence / comparison / timeline / data / prose 分类。
- 内嵌本地 Mermaid，在打开／预览时生成 SVG，并提供缩放／拖动／展开控制；截图等待图渲染完成。源码转义与图渲染失败显式处理，不通过 CDN 补救。
- 为 SVG／图表／代码路径提供轻量辅助函数，不要求所有内容使用同一组件树。
- 离线打包解析资源并内嵌许可允许的内容；无网络实际打开，检查字体、图、表格、脚本和键盘。
- 页面有正文阅读宽度和分层导航，复杂图独立展开，不能把长文变成全屏卡片轮播。

双语源码恰好包含两个不嵌套的顶层本地化根：`<section data-aha-lang="en" lang="en" data-aha-title="English title">` 和 `<section data-aha-lang="zh" lang="zh-CN" data-aha-title="中文标题">`，各自闭合并包含完整解释。作者自由设计布局，可共享中性图形／资源，但根外不留未翻译的读者正文。

运行时校验两分支非空及标题，注入离线语言按钮，切换 `html lang` 和文档标题，以 `hidden` 加 CSS 隐藏非活动分支及其焦点目标；向 `window` 派发 `aha:languagechange`，`detail.language` 为 `en` 或 `zh`，供作者可选交互使用。Mermaid 运行时标签按所在分支／根本地化。不使用 `localStorage`、网络或语言 URL 参数，不推断或持久化语言偏好；双语初始始终是英语。语言切换与现有主题选择规则独立。

验收样例必须包含长正文、宽对比表、时序图和一个有用的交互；分别检查桌面、窄屏与减少动画。

双语验收必须真实切换并检查两完整分支、键盘访问、隐藏焦点目标、标题／lang 与 Mermaid 控件。检查中文字体和较长英文标签，并逐项核对单位、否定、不确定性、限制与引用。未审阅的译文不能宣称准确。

### 5.2 一图流：复用渲染基础，不复用网页布局

从研究选一个主线，独立设计纵向分区或横向关系，保留必要来源摘要。支持自选尺寸和清晰度预算；超出浏览器截图能力时报告并协商尺寸／分块，不悄悄截断。

复用本地浏览器捕获、字体就绪与裁切检测，捕获 `artifact.json` 所指定的完整视口，不依赖固定旧卡片 ID，也不提供根元素选择器。完整图和阅读尺寸截图同时检查；文本内容回查研究。

图片默认英语、明确中文请求用 `zh`，不支持 `bilingual`。作者将所有标签、来源和限制编写为所选语言，不把研究原文直接当作已翻译内容。

### 5.3 PPTX：直接原生创作，不经 HTML 强制转换

保留 PptxGenJS 作为基础；作品脚本直接接收 `{ pptx, research }`，使用其原生文本、形状、图表、连接线与备注 API。旧 Pack renderer 已移除，不把它的固定布局助手包装成新的必经 DSL。文字测量与布局检查仍需按实际作品执行，不声称已有通用自动排版器。

先分配页级论证和布局，再写内容。标题、机制图、数据、对照、代码、总结和附录根据职责选择不同构图。移除新路径的旧 12 页硬约束，但保留明确的资源／页数预算防止失控；预算不足应拆分或协商。

正文与来源覆盖检查、OOXML 回读、逐页实际渲染和原生可编辑性检查分别执行。没有可用 PowerPoint／兼容渲染环境时，不把 HTML 预览当作 PPTX 验收。

复杂 Mermaid／SVG 可作为图像对象插入并声明编辑限制；尽可能用原生文本与形状表达核心关系。不能承诺任意 SVG 自动无损变成可编辑图元。

PPTX 默认英语、明确中文请求用 `zh`，不支持 `bilingual`。标题、原生文本、图表、读者备注与引用按所选语言编写并检查字体和标签长度；作品字段不证明演示应用的语言设置已正确写入，不承诺未经核实的原生 API 支持。

### 5.4 视频：保留音频基础，重写画面生成

保留已有 Edge TTS 适配、实际音频时长、旁白身份、网络审批、用户音频导入、FFmpeg 封装与错误报告。

视频默认英语、明确中文请求用 `zh`，不支持 `bilingual`。`prepare-video` 新计划按作品语言选择 `en-US-JennyNeural`（`en` 或旧元数据缺失语言）或 `zh-CN-XiaoxiaoNeural`（`zh`）。计划仍显式保存 `voice`，已有作者计划不被改写。作者编写目标语言 `segments[].text`，草稿建议不自动翻译；烧录字幕与 SRT 从该文本派生，也不自动翻译。翻译旁白会改变计划哈希，须重新校验并完整批准当前旁白、提供方、声线、语速和外发范围。

新 VideoPlan 与独立研究／作品身份绑定，不再以 `narrative.slides[].notes` 作为唯一旁白来源。加入稳定 segment / scene 身份、旁白、字幕块、分镜职责、时序锚点和所用 Claim。

新实现选择浏览器逐帧 HTML／SVG／canvas 与 FFmpeg，复用现有工具，不增加专用动画引擎依赖。按相同机制小样验收：具体内容从 A 到 B、一次条件变化、局部强调、旁白与字幕。它不是 Remotion 集成；专用动画库留待真实创作需求证明必要后再评估。

镜头时间由音频与锚点计算，不在散落镜头中手工硬编码整片帧号。视觉用画面内动作解释过程，不能只对静态页面加转场。静态画面可用于阅读或停顿，但不要求保留旧卡片视频管线作为兼容产品。

QA 从字幕安全区、画面可读、关键动作与旁白时机开始，再添加与实际场景相关的动效检查。静止可用于阅读与强调，不照搬其他风格“所有元素必须持续动”的阈值。

任何新旁白版本重新审阅外发。当前版本保守地将音频计划绑定整个作品源哈希：即使只改背景，也会使旧计划／音频身份失效，不能直接复用或手改 hash。已有不重合成的显式路径：生成新计划，复核未变旁白并选择 `provided-audio`，批准新哈希后将旧音频重新导入新目录；来源如实记为本地提供音频。旁白身份与视觉修订的自动解耦留待后续实现，不承诺自动增量重建。

## 6. 工具层：保留能力，解除耦合

### 按阶段加载与检查

两个 Skill 的 description 明确最终交付边界，入口按取证、草稿、创作、设计、执行、验收逐步加载参考；只有需要时读取所选主题章节或完整研究示例。没有新增产品 Skill，也不依靠宿主自动互调。

`research-check --draft` 与严格检查共享校验逻辑：未知引用、重复 ID、非法元数据、显式矛盾链接等仍失败；可补全的内容报告为 `pending`。草稿检查始终 `ready: false`，不生成快照身份；严格 `research-check`／build／validate 的完成条件不变。

`doctor --for research|html|browser|image|pptx|video|speech` 只探测当前步骤的可选工具；原 `--media` 保留为互斥的全媒体诊断入口。基础运行时检查不调用 Python／FFmpeg／浏览器；视频探测不调用 TTS，speech 不调用浏览器。诊断结果区分检查范围与缺失项，不把媒体工具缺失升级为所有任务的阻塞，也不将本地探测当作真实在线合成或作品验收。

当前主干已经切换，模块职责如下：

| 位置 | 当前职责 | 边界 |
| --- | --- | --- |
| `skills/aha-research`、共享研究参考 | 深入调研流程与独立研究契约 | Agent 实际取证，CLI 不伪造调研 |
| `skills/aha-explain`、按媒介参考 | 内容策划、自由创作与质量回查 | 不新增格式 Skill，不自动全格式输出 |
| `src/research/*` | Schema、引用／证据检查、三文件档案 | 不支持旧 Pack，不认证语义真值 |
| `src/core/check.ts`、`errors.ts`、`identity.ts` | 通用类型检查、错误、规范化身份 | 旧模型／实验／教学协议已删除 |
| `src/artifacts/*` | 项目、源身份、离线打包、PNG、原生 PPTX 与回执 | 作者源码为权威；执行需授权 |
| `src/browser/mermaid.ts` | 本地 Mermaid 与图形操作控件 | 不联网加载图形库 |
| `src/media/*` | 新旁白计划、音频、逐帧浏览器视频与编码 | 实测音频；未执行真实在线合成不能标为成功 |
| `src/cli/*` | 研究／创作命令、参数与审批检查 | 旧命令明确失败，无兼容别名 |
| `scripts/*` | 构建、清单、独立双 Skill 发布与安装 | 不自动删除外部旧入口或覆盖安装 |
| `tests/*` | 新契约、CLI／分发、浏览器与离线动态视频 | 不替代人工视觉、听审和真实宿主路由 |

旧 `src/renderers`、`src/studio`、Lab／Story 源码与只服务它们的测试已退出主干。仓库忽略规则限定为根目录 `/artifacts/`，不能把新的 `src/artifacts` 源码误排除。

## 7. 信任模型是新路径的前置工作

旧 renderer 只处理受限数据，新模式会执行 Agent 编写的代码，风险模型已经变化。

1. 研究输入永远按数据处理；用户要研究代码不等于授权运行被研究仓库。
2. 静态检查不执行作品。实际浏览器预览使用独立环境、不带登录状态，阻断未批准网络和权限，限制本地文件范围。
3. PptxGenJS／动画项目构建属于 Node 执行，不能仅靠浏览器请求拦截来隔离。优先使用受限执行环境、工作目录挂载和明确依赖清单。
4. 没有真正隔离时，必须通过宿主取得针对作品构建的明确本地执行授权并披露权限；无法取得就只交源并说明缺失渲染，不自动打开未审作品。
5. 依赖安装、外部模型／TTS、文件分享分别有授权；不默认自动下载浏览器、字体或 npm 依赖。
6. 交付中默认只包含读者需要的内容和获准引用；完整研究档案独立保存。旧产物本来内嵌 Pack，迁移器不得错误宣称旧文件已被脱敏。

沙箱、来源文本转义、资源清单、静态检查、语义审阅各解决不同问题，不能互相替代。

## 8. 版本与旧数据处理

建立独立研究协议与作品协议，不要求维持 Pack 0.1.0 的运行兼容。新工具遇到旧包时明确不支持，不伪装成已迁移，也不修改或删除原文件。

有具体旧研究需要复用时，再提供显式的一次性提取：记录原身份，读取 brief / claims / evidence / research，报告缺失日志和新字段；保留原文件，不用默认值伪造研究。旧模型结果不能升级为真实观察，不把一次性迁移变成长期兼容产品。

新作品显式指向研究版本。初版实现版本不符检查和显式重建；受影响作品清单与自然语言隐含依赖仍需 Agent 复核，不承诺自动影响分析或完整增量重算。

只改设计时复用相同研究；改事实时新建研究修订，列出受影响作品。发布目录使用新快照，旧有效产物可恢复。对用户直接在 PPTX 中做的编辑，须说明是否已同步回源，不能下次重建静默抹掉。

| 顺序 | 工作单元 | 依赖与验收 |

## 10. 验收集与效果判断

采用公开、合成或明确获准的材料，保存研究版本与环境：

- 开放问题：路线比较，包含原始来源、同源转载与反证。
- 代码问题：固定版本入口到存储路径，包含失败分支和文档／实现不一致。
- 混合问题：公开技术主张与某个实际实现的对照，不能互相替代证据。
- 复用主题：同一研究做富文本 HTML、一图流、原生 PPTX 与 Edge TTS 视频，事实一致而版式／叙事不同。

每个样例同时记录研究结论质量、关键断言支持、覆盖、画面检查、实际交互／播放、制作耗时与修订次数。缺授权或工具的项标未检查，不补造结果。

新的自动测试应覆盖：独立研究无模型也合法、引用失败定位、不支持的旧版本明确报错且不篡改文件、HTML 资源与 Mermaid、任意作品尺寸、PPTX 内容覆盖与原生对象、动态时间轴和音频绑定、失败保留旧产物，以及发布物恰好包含两个 Skill。

视觉自由度的关键验收：**至少三种不同结构的作品能由作品源完成，无需给共享 Schema 增加题材专属字段，也无需修改固定 renderer 才能表达。**

保留少量优秀作品与失败对照作为版本化验收资产；敏感研究和生成物继续放忽略的 artifacts 或获准目录，不要求提交用户原始材料。参考作品是质量标尺，不是“所有作品长得一样”的模板。
