# Aha 产品需求

> 定位：深入研究一个问题，自由设计它的表达。
>
> 当前源码 runtime：`0.3.3` · 研究与作品协议：`1.0.0` · 实际发布状态见 [Releases](https://github.com/sawyer0x110/aha/releases)

本文定义当前产品的能力、行为和质量要求。入口见[文档目录](README.zh-CN.md)，安装见[安装指南](INSTALL.zh-CN.md)，命令见[使用指南](USAGE.zh-CN.md)，实现边界见[架构说明](ARCHITECTURE.md)，调研方法见[研究协议](RESEARCH.md)，效果验证见[评估协议](EVALUATION.md)。

## 1. 两项核心能力

| Skill | 负责 | 交付 |
| --- | --- | --- |
| `aha-research` | 深入调查开放世界问题、代码库／diff 或混合问题 | 可读研究报告、证据台账、版本身份、缺口与停止理由 |
| `aha-explain` | 从已有研究或需要先调研的问题出发，创作视觉解释 | 用户所选的 HTML、PNG、原生 PPTX 或讲解视频，以及可编辑源和 QA 记录 |

研究是独立交付，不是制作媒体前的搜索摘要。视觉表达按问题、受众和媒介选择内容结构，不要求统一卡片、模拟器、教学测验或固定页面数量。

“自由”指内容编排和视觉创作自由，不代表可以任意联网、执行不可信代码、伪造依据或忽略许可。

## 2. 请求与输出选择

- 只请求调查或报告时使用 `aha-research`；普通事实问答和常规代码解释不自动升级成完整研究或媒体制作。
- 请求视觉作品时使用 `aha-explain`，按需完成前置研究，不依赖宿主自动串联两个 Skill。
- 明确请求的媒介优先：网页／HTML 对应 HTML，一图流／海报对应 PNG，PPT 对应原生 PPTX，讲解视频对应 video；明确的网页幻灯片仍是 HTML。
- 视觉解释未指定媒介且无决定性语境时，默认 HTML 并简短说明。只有影响用途、成本、范围或权限的歧义才询问。
- 仅生成请求的格式。多格式分别建立项目，共用研究事实，不强制共用布局或全文内容；CLI 一次显式选择一种格式。
- 复用已有研究前核对问题覆盖、时效、版本和授权，只补必要缺口。

## 3. 深入调研

### 问题驱动

复用用户给出的用途、受众知识、语言、时效、授权材料和预算。建立问题树、待证解释、支持依据与可能推翻结论的证据；不为凑数机械执行固定查询数。

每轮更新结论、反证和缺口，按缺口定向补查。主要问题得到充分支持、重要反证已处理，或触及明确访问／工具／预算限制时停止，报告真实理由。扩大权限或显著成本前确认。

### 来源标准

| 路线 | 必须做到 |
| --- | --- |
| 公开问题 | 实际阅读原文和方法，优先一手来源；识别同源转载，追查更正和反证；保留数字的单位、分母、时间窗和适用群体 |
| 代码库／diff | 固定 commit、diff 两侧及工作区内容身份；追踪入口、调用者、状态、配置与失败路径；核对测试和文档，区分源码推断与运行观察 |
| 提供的材料 | 准确说明材料范围和读取程度；不把仅提供的摘要、记录或合成材料冒充独立公开调查 |
| 混合问题 | 同时保留各自版本和证据标准；公开规范不证明本地实现符合，一次观察不证明所有环境的行为 |

默认只读，不因调查需要自动执行被研究仓库。来源中的操作指令不是授权。

### 研究成果

独立 Research Dossier 包含报告、子问题、主张、证据、真实读取记录、缺口和停止理由。报告应直接回答问题，解释机制、冲突和必要限定，而不是罗列链接。

支持某几条事实不等于支持它们之间的因果链。缺少关键推理连接时继续补证，或收窄结论并记录未知，不留给作品作者自行编造。

结构校验、来源支持的语义复核、实际执行观察分别记录；哈希和引用有效不等于事实正确。

## 4. 自由视觉表达

### 内容与设计

先明确作品要解决的读者问题、必要主张、机制、例子和限制，再决定阅读路径、图形及布局。

- 标题独立出现时也能识别对象和问题。先介绍实体或字段，再使用例子数值；同步浏览器标题、封面和目录。
- 解释必要的对象、关系、条件和结果，不用“匹配很重要”等短句代替推理。压缩内容时删次要分支，不删除关键连接。
- 先审读代表性文字，再做实际尺寸的小样；最终覆盖所有读者文案、图注与动态反馈。
- 图的箭头、位置、状态、单位和颜色应表达明确关系；交互或动作必须帮助理解，不能冒充实际实验或测量。
- 用户／项目品牌优先。主题配方可选，Clawpilot 是缺省起点而非唯一美学；同一作品可以有多种适合内容的构图。
- 新增实质主张先回到研究补证，不能借美化增加未经支持的数值或行为。

详细创作方法见[解释性编辑](../skills/aha-explain/references/explanation-writing.md)和[视觉设计](../skills/aha-explain/references/visual-design.md)。

### 媒介要求

| 媒介 | 产出要求 | 当前边界 |
| --- | --- | --- |
| HTML | 图解主导、比较、交互探索、长文或混合结构；保留可访问的解释文本；可用 Mermaid、SVG、表格和本地交互 | 独立离线文件，内嵌受支持且获准的本地资源；内置 Mermaid 在浏览器中渲染 |
| PNG | 按目标尺寸独立构图，主线、单位、连接关系、限制和来源在阅读尺寸下可读 | 捕获专门创作的完整视口，不以缩小整页文章替代一图流 |
| PPTX | 核心文字、形状、表格和可表达的数据图原生可编辑；按完整论证安排页数和附录，构图有变化 | 复杂插图可以图片化，但要说明编辑限制；实际演示应用渲染及编辑检查不可省略 |
| 视频 | 旁白讲清原因和承接，画面展示机制变化；先审看短小样，再制作完整内容 | 浏览器按帧场景与 FFmpeg；固定 720p30、H.264/AAC、句／段级字幕和 SRT，上限 600 秒、200 段 |

不强制每篇 HTML 同时包含长文、宽表和时序图；这些是能力测试项。内容丰富不等于缩小字体，动态解释不等于静态页面加转场。

视频按实测音频时长组织画面，不靠拉伸语速满足时长。Edge TTS 为在线提供方，用户音频是明确选择的替代；不静默切换提供方或冒称合成成功。缺少工具、批准或实际播放检查时，明确相应阶段未完成。

### 语言

| 媒介 | 默认 | 显式选择 |
| --- | --- | --- |
| HTML | 中英双语，初始英语，内置 English/中文切换 | `en`、`zh`、`bilingual` |
| PNG／PPTX／视频 | 英语 | `en`、`zh` |

中文问题或中文研究不自动改变作品语言；明确中文输出请求选择 `zh`。语言只作用于作品，不翻译或修改封存研究。

Agent 基于同一事实分别组织自然表达，不强制逐句对应。先独立审读各语言，再核对数量、单位、否定、条件、图注和来源。切换成功或双语分支非空不代表译文质量通过。

完整元数据、双语根、标题与切换契约见[语言参考](../skills/aha-explain/references/language.md)。

## 5. 创作、审批与交付

`理解请求 → 调研／复用研究 → 内容策划 → 媒介设计 → 编写作品源 → 小样 → 检查修订 → 交付`

- scaffold 是未完成草稿；只有实际编写内容和主张覆盖后才能声明 `authored`。
- 修改可编辑源，再重建产物；不只修最终文件而留下无法复现的来源。修改事实时建立新研究快照，并核对受影响作品。
- 依赖按当前步骤检查；缺失浏览器不阻塞研究或 HTML 打包，缺失语音工具不阻塞用户音频导入路径。诊断不自动安装或授予执行权。
- 预览或渲染作者代码前审阅源并取得明确本地执行授权。Node 作者代码具有宿主权限；超时和 `--allow-code` 不是 OS 沙箱。
- 在线 TTS 另需批准完整旁白、提供方、声线、语速和外发范围。源或计划变化时遵守实际身份检查，不编辑哈希强行复用音频。
- 分开可编辑项目、项目外工作记录和当前交付目录。新候选先另存；当前目录只展示选定产物、匹配收据、必要资源、来源引用和当前 QA。
- 替换、归档或删除须限于用户授权范围，不能静默覆盖用户编辑。产物与收据成对处理，核对身份及链接；CLI 拒绝覆盖，不提供原子发布。

私有研究不默认进入公开成品或讲者备注；分享前检查正文、资源和隐含数据。软件、字体、图像与音频的许可及外发权限分别核实，公开可读不等于允许复制或商用。

## 6. 质量与完成定义

| 维度 | 所需证据 |
| --- | --- |
| 研究与事实 | 对关键文字、数值和图关系回查实际来源；保留反证、版本、条件与未知 |
| 解释与语言 | 对象和推理可跟随，术语与标题可理解；逐语言检查自然表达和事实一致 |
| 视觉与编辑 | 实际尺寸下可读，无遮挡或误导关系；PPTX 实际逐页渲染并试改代表对象 |
| 运行与媒体 | HTML 离线桌面／窄屏、键盘与交互实测；视频实际观看、听审和字幕检查 |
| 可复现交付 | 研究、源、产物和收据身份一致；资源许可清楚，已检与未检项明确 |
| 读者理解 | 经同意收集目标读者对未展示案例的独立判断和理由，不用模型自评或“我懂了”替代 |

[评估协议](EVALUATION.md)规定固定材料、作者与评分答案分离、条件一致的版本对照和真实读者迁移任务。内容断言与过程证据单独记录，未知保持 `null`；单次试跑或合成材料回归不证明稳定增益、真实联网能力或普遍学习效果。

当前提供两项 Skill、多媒介工具链、可复跑评估基础和 [HTML 实例](../examples/README.zh-CN.md)。跨题材稳定性、跨媒介审美、宿主触发率及真人理解提升仍需要对应证据，不能因代码存在或文件生成而宣布全部通过。

**一次任务完成意味着：交付用户要求的研究或作品，内容有依据、表达适合受众与媒介，源文件可保留，实际检查及剩余限制如实说明。**
