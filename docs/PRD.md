## 1. 产品概述

Aha 将一个问题及其依据转化为两类学习体验：

- **Aha Lab：自己探索，弄懂为什么。** 输出浏览器可打开的交互 HTML，提供实验、对照、状态回放或证据探索。
- **Aha Story：通过讲解，让别人理解。** 输出 HTML slides 或短视频；后续增加原生可编辑 PPTX。

两个 Skill 共用版本化的 Explanation Pack（解释包），避免对同一个主题各自理解、各自生成，导致结果互相矛盾。

产品不是代码专用工具。输入可以是概念、文章、文档、数据、用户提供的材料或代码仓库。代码是易于建立可执行依据的一类输入，而不是产品边界。

核心价值不是“一键导出三种格式”，而是：

**先形成有依据、可理解的解释，再让它既能被探索，也能被传播。**

### 1.1 对“解释任何事情”的限定

“广泛主题”意味着允许不同问题进入产品，不意味着所有主题都有可计算答案，也不意味着对所有领域具有同等准确性。

- 可计算机制：可以改变输入并计算结果，例如复利、缓存、排队模型。
- 过程与状态：可以回放步骤、比较路径，例如工作流、重试、审批。
- 证据与观点：可以探索来源、时间线和不同解释，例如历史与公共议题。
- 主观或开放问题：提供有出处的观点比较，不伪装成唯一正确答案。

不支持的主题或模型必须明确说明，允许产出较简单的阅读／讲解材料，而不是强行放几个无意义的滑杆。

## 2. 用户、任务与价值

| 用户 | 任务 | 现有问题 | Aha 的预期价值 |
|---|---|---|---|
| 自主学习者 | 理解一个抽象概念 | 看懂文字却无法预测结果 | 改条件、先猜再观察 |
| 软件工程师 | 理解模块或解释实现 | 读代码缺乏整体过程感 | 输入、分支、状态与源码关联 |
| 技术分享者 | 向团队讲清一个机制 | 重复做图，材料和 demo 不一致 | 从同一解释包产出实验与讲解 |
| 教师／培训者 | 组织一个短教学单元 | 素材与互动练习相互脱节 | 引导案例、自由探索与演示材料复用 |
| 分析人员 | 解释指标、假设或方案 | 图表没有说明假设和限制 | 展示计算依据与假设敏感性 |

首发用户优先为成人学习者与技术分享者。Aha 不是默认面向儿童的产品；儿童版的同意、隐私、内容与教学要求需另行设计。

## 3. 使用场景

### 3.1 从一个问题开始

用户：“为什么同样是平均涨幅，最后资产可能不同？”

系统明确解释范围为简单收益率路径与复利，不自动引入投资建议。生成一个可修改涨跌幅的 Lab，并说明：固定同一组收益率、没有中途现金流时，仅改变排列不改变最终乘积；加入不同时点现金流后，顺序才可能改变最终资产。

这个案例要求产品纠正问题中隐含的错误前提，而不是为了有趣而编造“顺序一定改变结果”。

### 3.2 从代码开始

用户：“解释这个 repo 的重试逻辑，让我调整失败次数和退避参数。”

系统定位相关实现与测试，识别最大尝试次数、可重试错误、延迟策略和取消条件；确认是否允许隔离执行。Lab 展示规范化事件轨迹；Story 复用相同案例讲清差异。

### 3.3 从文章开始

用户提供文章：“讲清这篇文章对城市拥堵的解释。”

系统拆分作者主张、引用依据、假设和遗漏。仅有相关性资料时提供证据浏览和观点对照，不自动构建“修路多少就减少多少拥堵”的因果模拟器。

### 3.4 从探索到传播

用户在 Lab 中运行两个案例，选择“保存为讲解案例”，附加“这里与我的预期不同”的笔记。

Story 导入该探索记录，验证解释包版本和案例轨迹，然后生成六页 slides 或一段 60–90 秒讲解视频。无需再次读取全部材料。

### 3.5 Story 独立使用

用户直接要求短视频时，Story 可以自行建立解释包、案例与叙事，不强制先交付 Lab 页面。

## 4. 产品目标、非目标与差异

### 4.1 目标

1. 将一个聚焦的问题转化为适合该问题的互动或讲解。
2. 将结果、解释与证据关联，明确区分事实、模型和推测。
3. 支持输入变化真正改变结果，而非只有装饰性互动。
4. 让 Lab、slides 与视频使用一致的关键事实与案例。
5. 交付可保留、可重播、可迁移的文件，而不是只存在于聊天记录中。
6. 让生成失败、来源不足、执行受限等情况有明确边界。

### 4.2 非目标

- 不承诺任意主题自动生成准确模拟。
- 不建立通用自主研究平台、多 Agent 平台或新代码搜索引擎。
- 不默认执行陌生仓库、联网抓取全部链接或安装依赖。
- 不做任意网页转视频或全功能绘图编辑器。
- 不提供医疗、法律、金融等个体化高风险决策建议。
- 不以点击量、停留时间或游戏奖励代替学习效果。
- 不在 MVP 提供账号体系、公开作品社区、协同编辑或计费系统。

### 4.3 差异化门槛

若产物只有图形、节点点击、路径播放和来源链接，应优先考虑已有可视化工具，而不是声称 Aha 已有独立价值。

Aha 的核心差异应至少体现一种：

- 输入改变后产生新的、可解释的行为结果。
- 真实轨迹与模型结果有可观察的对照。
- 一次探索形成的案例可以直接转换为一致的讲解。
- 不适合模拟的主题采用证据交互，清楚保留不确定性。

## 5. 产品组成与交付物

| 组成 | 职责 | 用户可见交付 |
|---|---|---|
| `aha-lab` Skill | 确定问题、建立实验或探索页 | `topic.lab.html` |
| `aha-story` Skill | 组织叙事、分镜与输出 | `topic.slides.html`、`topic.mp4` |
| Pack 内核 | 存储主题、依据、案例、轨迹、叙事 | `topic.aha/` |
| 本地工具库／CLI | 校验、运行受支持适配器、渲染、打包 | 机器可读结果与错误 |
| Explore Session | 导出用户实际选定的案例 | `topic.exploration.json` |

拟议调用示例，不是已安装命令：

```text
/aha-lab 解释为什么排队在接近满负荷时变慢，面向普通成年人。
/aha-story 用刚才选中的两个案例生成 6 页中文 HTML slides。
/aha-story 解释这个文件里的缓存淘汰逻辑，生成 90 秒视频。
```

产品分为“作者侧”和“观看侧”：作者侧可使用宿主 Agent、模型与受控工具；观看侧的离线 HTML 不要求模型密钥或开发环境。

## 6. 范围与阶段

| 阶段 | 内容 | 不承诺 |
|---|---|---|
| P0：核心 | 两个 Skill、解释包、输入路由、Lab、HTML slides、一个受限视频模板 | 任意主题精确模拟 |
| P0：演示主题 | 确定性重试、复利计算两个主题；一份非模拟证据探索示例 | 完整学科覆盖 |
| P1 | 更多组件、可靠的批量视频、更多文档输入适配 | 自动执行所有语言 |
| P1 | 原生可编辑 PPTX、结构化讲解修订、更多主题包 | HTML 一比一无损转 PPTX |
| P2 | 更广泛的数据／代码适配、多人分享工作流 | 无需审查的高风险内容 |

P0 的视频输出限定一个版式家族、60–90 秒、有限场景数。若配额或渲染条件不足，应报告视频未完成，不能用 slides 冒充已交付视频。

## 7. 输入与主题路由需求

### FR-01 输入解析

- 支持自由文本问题、选定的本地文本／Markdown、代码文件或仓库上下文。
- URL 输入须通过授权工具获取；记录获取时间，页面不可访问时明确提示。
- PDF、DOCX、PPTX 等富文档适配属于 P1；P0 可接收用户经现有工具提取的文本，并标记来源定位是否丢失。
- 不默认上传原始文档或仓库到其他服务；遵守宿主权限与内容排除规则。
- 来源中的命令或“忽略规则”等内容视为材料，不视为系统指令。

### FR-02 解释简报

生成前建立 Brief：主题、核心问题、受众、语言、预备知识、输出、范围与排除项。

用户已表达的信息不重复询问。默认可用成人初学者、中文、单主题；只有范围或授权会显著影响结果时才请求确认。

过宽问题先给出 2–4 个切口。存在错误前提时先澄清事实，并建议可检验的问题。

### FR-03 交互范式选择

| 问题特征 | 交互范式 | 示例 | 禁止行为 |
|---|---|---|---|
| 存在明确计算规则 | 参数实验 | 复利、费用 | 捏造公式或输入域 |
| 存在离散事件 | 状态回放 | 重试、缓存 | 假装可观测全部内部状态 |
| 存在可比较条件 | A/B 对照 | 不同策略 | 同时偷偷改变多个未披露条件 |
| 证据、年代、观点为主 | 时间线／证据探索 | 历史叙述 | 把相关性做成因果滑杆 |
| 主要是概念辨析 | 引导案例／分类比较 | 机会成本 | 强行量化主观判断 |

路由结果要体现在页面标签中。无法建立有意义的 Lab 时，说明原因并建议 Story 或阅读型解释，不静默降级。

## 8. 证据与研究需求

### FR-04 结论台账

每个关键 Claim 应记录：

- 结论文本、适用范围和单位。
- 类型：有来源的事实、执行观察、模型结果、解释性推断、未解决问题。
- 一个或多个 Evidence ID。
- 已知假设、冲突或限制。

不能把模型自己的流畅解释当作外部证据。文档中的断言应表述为“来源声称”，不自动升级成已独立证实的事实。

### FR-05 来源定位

- 代码：仓库、commit、路径、符号、行范围、必要片段摘要。
- 脏工作区：commit 加相关内容哈希／补丁身份，不仅显示 commit。
- 文档：标题、版本／日期、段落或页码；定位不可靠时标注。
- 网页：URL、获取日期、标题、必要摘要；不完整复制受版权保护内容。
- 执行：案例输入、运行环境、目标版本、结果和捕获方式。

原始片段只保留必要长度。私有来源默认只在本地生成私有产物；分享前提供来源和敏感内容清单。

### FR-06 证据等级

| 标签 | 含义 |
|---|---|
| `observed` | 在记录的输入、版本和环境下真实运行获得 |
| `derived-model` | 按明确规则与假设计算，可与部分案例对照 |
| `illustrative` | 帮助理解的示意，不证明真实世界或仓库行为 |
| `source-based` | 基于材料的解释或比较，不主张可执行性 |

标签可以细化到案例，不仅是整个页面。来源链接存在、Schema 合法、若干测试通过，都不等于所有语义正确。

## 9. Aha Lab 功能需求

### FR-07 页面结构

1. 问题与适用边界。
2. “带我理解”：一个最小案例的引导播放。
3. “让我试试”：参数、案例选择与运行。
4. 状态／过程主视图。
5. 结果、差异与“为什么”。
6. 来源、假设、模型版本和未知项。

没有参数模型的主题将第 3 项替换为证据、时间线或观点选择，不伪造运行按钮。

### FR-08 运行与单步

- 支持运行、暂停、继续、前后单步、重置。
- 每个步骤对应语义事件，而不是装饰动画帧。
- 状态由事件和状态归约器推导；前后跳转保持一致。
- 动画不改变计算规则，改变播放速度不改变结果。
- 参数输入包含单位、范围、离散／连续类型与默认值；非法输入有错误提示。
- 模型无法处理的输入不截断成一个“看起来合理”的结果。

### FR-09 对照实验

- 保留 A、B 两组输入与结果，明确列出不同字段。
- 同一引擎版本下比较；版本不同需醒目标记，不作为纯输入因果对照。
- 支持从预设案例开始，默认只改变一个主要变量。
- 比较实际结果和用户预期为可选功能，不打分羞辱，不以答错惩罚用户。

### FR-10 状态解释

- 结果说明来自当前事件的规则映射、参数和证据，不在每次交互时重新请求模型。
- 解释可引用当前数据，例如“错误类别不在允许重试列表中，因此停止”。
- 无可观察内部轨迹时只展示输入输出，不能用虚构内部步骤补满页面。
- 点击结果或事件可展开证据；缺少证据时展示未知，不显示误导性的“源码已验证”。

### FR-11 探索记录

- 用户选定输入、轨迹、观察备注后，可下载 `exploration.json`。
- 记录 Pack ID、Pack 哈希、引擎版本、场景、参数、种子、轨迹哈希。
- 离线 HTML 无需任意写磁盘权限；通过显式下载导出，Story 再导入。
- 备注不是事实依据，不能未经核实进入视频旁白。
- 导入时验证大小、结构、Pack 关联与兼容性；不执行其中的脚本。

## 10. Aha Story 功能需求

### FR-12 叙事规划

支持从 Brief 新建，也支持从解释包或探索记录继续。

提纲包含：受众、学习目标、关键疑问、案例、段落、总长度、事实引用与限制。视频生成前请求用户确认提纲和旁白；明确确认过的内容在续跑时复用，不重复打断。

推荐顺序：疑问 → 最小模型 → 正常案例 → 条件变化 → 结果原因 → 边界与探索入口。

### FR-13 案例驱动讲解

- 分镜引用 Scenario、Event 范围和 Claim ID。
- 需要新案例时先取得轨迹或模型结果，再写入讲解。
- 视频不伪装成现场真实执行，不把逻辑时间当实测耗时。
- 来源和示意标签不能仅存在于解释包；主产物要保留可读标识与来源入口。

### FR-14 HTML slides

- 默认 5–8 页，16:9 演示布局，支持键盘、触控、全屏、页码与备注。
- 一页围绕一个主要结论，图形和文字共同表达。
- 从轨迹提取关键状态，可分步展开，但不要求观众操作实验控件。
- 视频旁白不能直接全部塞进页面，详细内容进入演讲备注。
- 完整嵌入所需样式、脚本和许可允许的资源；默认不依赖 CDN。
- 可选链接回 Lab；私有链接不自动发布，不保证接收者有访问权限。

### FR-15 视频

- P0：1280×720、30fps、H.264 MP4，默认 60–90 秒。
- 中文优先；一条许可明确的合成声线，字幕与已确认旁白一致。
- 先生成音频并获取实际时长，再形成镜头时间线。
- 单词时间戳或强制对齐不可用时采用句级字幕，不声称词级精确同步。
- 镜头由状态、轨迹和有限动画词汇组成；不依赖生成式视频模型。
- 可以复用渲染组件，但为视频重新布局，不直接录制整个 Lab 页面。
- 音频、字幕、字体、画面和来源页均纳入交付检查。
- TTS 失败时询问重试、用户提供音频或明确选择无配音版本；不静默改成另一种交付。

### FR-16 修订与续跑

允许修改受众、篇幅、叙事或视觉样式而不重新获取全部证据。

修改某个 Claim、规则或案例输入时，标记依赖它的轨迹与产物过期；修改配色不应触发模型重新推导行为。

每次产物记录 Pack 哈希、叙事版本、渲染器版本与必要配置。

## 11. 解释包结构

建议磁盘结构：

```text
topic.aha/
  manifest.json
  brief.json
  claims.json
  evidence.json
  model-spec.json
  scenarios.json
  traces/
    baseline.json
    comparison.json
  narrative.json
  assets/
  receipts/
```

执行适配器或生成的程序放在独立、需要授权的工作目录，不因为打开解释包而执行。

### 11.1 核心字段

| 文件 | 内容 |
|---|---|
| manifest | schemaVersion、packId、主题、语言、受众、内容哈希、可见性、来源版本 |
| claims | 有界结论、类型、证据引用、冲突、假设 |
| model-spec | 引擎标识、版本、参数、单位、输入域、简化项 |
| scenarios | 输入、种子、预期断言、执行／模型模式 |
| traces | 规范化事件、观测输出与重放所需状态 |
| narrative | 章节、旁白、镜头、事件引用、来源引用 |
| receipts | 各项检查结果、环境、失败原因与产物身份 |

哈希用于一致性和过期检测，不等于签名、可信来源证明或安全认证。

### 11.2 事件示例

```json
{
  "eventId": "event-4",
  "step": 4,
  "kind": "retry_scheduled",
  "logicalTimeMs": 1000,
  "stateBefore": { "attempt": 1 },
  "stateAfter": { "attempt": 2 },
  "details": {
    "delayMs": 1000,
    "reasonCode": "retryable_error"
  },
  "evidenceIds": ["retry-branch", "backoff-rule"]
}
```

事件需区分逻辑时间与观测耗时；状态字段和数值单位由主题适配器定义。通用 Schema 只保证结构，主题校验器负责规则与不变量。

## 12. 系统架构

### 12.1 模块

| 模块 | 职责 | 是否调用 AI |
|---|---|---|
| Skill 层 | 理解任务、确认范围、编排阶段 | 使用宿主 Agent |
| Source adapters | 获取授权材料、保留定位 | 通常不需要 |
| Pack builder | 组织 Claim、案例与叙事草案 | 可以 |
| Schema / semantic validators | 结构、引用、参数、不变量检查 | 硬规则不依赖 AI |
| Scenario engine | 执行内置模型或授权适配器 | 不需要 |
| Trace store / reducer | 规范化、重放、快照 | 不需要 |
| Visual components | 时间线、状态容器、数值图、证据卡 | 不需要 |
| Lab renderer | 参数交互与探索导出 | 不需要 |
| Story renderer | slides、分镜、视频 | 配音可调用服务 |
| Delivery pipeline | 打包、检查、原子替换 | 不需要 |

拟议技术栈为 TypeScript、Node.js LTS、浏览器 JavaScript/SVG；使用 JSON Schema 做可交换契约。具体包版本在实现时锁定。

两个 Skill 调用同一个本地工具库，不复制两套源分析与生成逻辑。第一版不要求独立 SaaS 后端或数据库。

### 12.2 工作流

`理解问题 → 确定范式 → 获取依据 → 建立解释包 → 准备案例 → 校验 → 生成 Lab / 叙事 → 渲染 → 交付`

关键状态：`draft`、`needs_clarification`、`awaiting_permission`、`evidence_ready`、`scenarios_ready`、`validated`、`rendering`、`delivered`、`failed`、`stale`。

任何阶段失败都保存必要上下文并明确失败点。最终文件只在检查通过后替换；保留上一份已知有效产物，不因半成品覆盖。

### 12.3 首批视觉组件

- 时间线：重试、等待、调度。
- 状态容器：缓存、队列、状态机。
- 数值图与明细：复利、费用、余额。
- 证据卡与对照列：文章观点、来源冲突。

采用语义视图规格选择组件，不让模型为每个主题无限制生成任意 HTML/JS。版式允许参数化，但运行逻辑来自受控组件。

交互不统一限定为“侧边参数面板 + 图表”。按学习任务评估三种控制方式：

- 叙述内控件：在句子中调整金额、容量或比例，关联文字与图形同步更新。
- 图中直接操作：拖动起点、移动对象或改变节点状态，同时提供键盘和表单等价操作。
- 证据操作：选择来源、事件或观点，对照依据而不是运行虚构的数值模型。

P0 每个主题只选一种最自然的主控制方式；先引导一个最小案例，再开放更多参数，避免一次暴露全部控件。

### 12.4 实时计算的边界

| 模式 | 单文件离线 HTML 能力 | 限制 |
|---|---|---|
| 内置声明式模型 | 修改合法参数并重新计算 | 仅限受支持模型 |
| 预录真实轨迹 | 切换案例、单步、对照 | 不能凭空支持任意新输入 |
| 外部真实执行 | 通过明确配置的本地执行服务调用 | 不再是完全独立离线文件 |

P0 优先前两种。外部执行服务不是默认开启功能。未提供时控件不能暗示可以实时运行原始仓库。

### 12.5 模型与执行能力

- 对代码案例，优先纯函数、小模块、已有测试接口。
- 只观测得到输入输出时，不构造“真实内部轨迹”。
- 插桩须在授权隔离副本中进行，并记录可能的行为影响。
- 并发时序不能用一次运行推断所有情况；P0 不做并发正确性证明。
- 主题模型将规则、参数域、随机种子和假设显式化。
- 金融数值按明确舍入规则处理，金额优先定点或十进制；展示精度与计算精度分离。
- 排队论、光学等新模型需主题专属依据与适用条件，不仅复用 UI。

### 12.6 视频技术选择

可评估 Remotion：React/TypeScript 场景、按帧确定性渲染、复用部分图形组件。Motion Canvas 同样列为候选：TypeScript 动画编排、实时预览、解释性矢量动画与配音同步，见 14.10。也可评估受控浏览器捕帧与编码，但不允许靠录制用户鼠标操作作为主要架构。

Remotion 的许可、组织使用要求、编码工具和字体许可必须在选型时单独核实；不能因为某参考项目使用它就假定无商业限制。

按事件索引与插值时间计算状态：Lab 用播放时钟驱动，视频用帧号驱动，slides 选取关键状态。固定随机种子，避免重渲染后画面或数值变化。

选型使用同一个 20–30 秒小样：三个状态、一次条件分支、两句旁白、字幕与一次源码／来源高亮。比较制作复杂度、时间定位、重复渲染结果、配音同步、目标设备渲染耗时、导出依赖和许可。P0 只选一个视频引擎，不同时维护两条正式视频管线。

### 12.7 HTML slides 技术选择

优先评估 reveal.js 承担翻页、渐进展示、键盘导航和演讲备注，Aha 负责内容、案例状态和视觉组件。PDF 导出不等于原生 PPTX；视频仍使用独立渲染流程。

若采用 reveal.js，须验证内嵌脚本、样式、字体、资源和备注功能在目标交付方式下的表现。支持浏览器演示不自动满足单文件离线承诺；仅交付已通过该模式检查的功能。

## 13. 技术难点与方案讨论

| 难点 | 不可靠捷径 | 建议处理 |
|---|---|---|
| 主题泛化 | 让 LLM 随便写模拟器 | 主题路由 + 少量引擎 + 显式不支持 |
| 源码忠实性 | 生成 JS 便声称等价于原代码 | 真实案例对照、模式标签、输入域限制 |
| 因果解释 | 看到相关就生成因果动画 | Claim 类型、来源与推断分离 |
| 所有格式一致 | 各自重新生成数值和文案 | 共用案例、事件与 Claim ID |
| 任意输入实时计算 | 在离线页面执行仓库环境 | 内置模型与真实轨迹明确分开 |
| 视觉质量 | 每次从零生成全部布局 | 固定组件、规则检查、实渲染检查 |
| AI 生成代码安全 | 把 Worker 当沙箱 | P0 不执行包内任意代码；授权执行需真正隔离 |
| 大型资料上下文 | 全量塞入模型 | 聚焦问题、追踪相关来源、记录遗漏 |
| 视频修改成本 | 先渲染完整成片再确认内容 | 提纲、旁白、小样先确认 |
| 来源更新 | 继续显示旧内容为最新 | 快照身份、哈希、过期提示 |

Web Worker 可以隔离 UI 计算和中止长任务，但不提供可靠的权限或恶意代码隔离。源材料、解释包、用户备注和生成产物全部视为不可信输入。

### 14.10 Motion Canvas：解释动画的候选引擎

- 仓库：https://github.com/motion-canvas/motion-canvas

README 描述了基于 TypeScript generators 的动画库、实时预览编辑器，以及面向解释性矢量动画和配音同步的设计。仓库包含浏览器播放器组件。

与 Remotion 的选型关系：两者列入同一个小样评估，不预先认定其一更快、更便宜或更适合所有主题。Aha 保留与具体渲染引擎无关的事件、案例和叙事层。

限制：浏览器能播放动画不等于已经支持 Aha 所需的任意参数重算、前后单步、真实代码轨迹或单文件离线。需要结合实际接口确认；不将播放器当作行为引擎。

### 14.11 Manim Community：数学主题的专项渲染

- 仓库：https://github.com/ManimCommunity/manim
- 文档：https://docs.manim.community/
- 许可：GitHub 元数据与 README 标注 MIT；字体、LaTeX 及其他依赖分别核实。

Manim Community 是以 Python 编程制作数学解释动画的引擎。它与 Grant Sanderson 维护的 `3b1b/manim` 是不同版本，不混用安装说明与接口。

借鉴／后续用途：

- 数学对象和变换的精确表达。
- 几何、函数、向量、概率等主题的专项视频。
- 用程序化场景保持可编辑性，而非依赖生成像素。

采用建议：作为 P1/P2 数学专项适配器候选，不纳入 P0 统一底座。Python 渲染与浏览器 Lab 是不同环境；成片不能直接视为可调参数的交互实验。

生成动画的数学表达仍需独立校验，使用 Manim 本身不保证讲解正确。

### 14.12 reveal.js：HTML slides 的基础设施

- 仓库：https://github.com/hakimel/reveal.js
- 文档：https://revealjs.com/
- 许可：GitHub 元数据与 README 标注 MIT。

README 列出分层幻灯片、Markdown、Auto-Animate、PDF 导出、演讲备注、数学排版、代码高亮和 API 等能力。

建议直接评估复用的部分：页面导航、渐进显示、演示控制和备注机制。Aha 应将开发资源集中在叙事、案例选择、关键状态与证据一致性，而不是重写成熟的演示基础设施。

边界：

- HTML 演示能力不等于视频制作流程。
- PDF 导出不等于原生可编辑 PPTX。
- 离线单文件需要额外打包，部分插件、字体与备注工作流需单独验证。
- 不默认启用远程托管、外部资源或第三方服务。

## 15. 安全、隐私与许可

- 陌生仓库的安装脚本、构建、测试都可能执行任意代码；运行前需要授权和真正隔离，不只检查文件扩展名。
- 执行环境默认无生产凭据、无宿主敏感目录、无网络，设置 CPU、内存、时间和输出上限。无法提供时禁用真实执行，明确可用替代。
- 私有材料的模型、TTS、视觉服务使用必须符合用户授权和组织政策，不默认跨供应商发送。
- 生成 HTML 的片段按文本转义，禁止将来源 HTML 原样插入；阻止未批准脚本、远程资源和路径穿越。
- 解释包设置版本、大小、资源类型和解压路径限制；P0 可先使用目录结构，不接受任意压缩包。
- 默认无遥测；诊断日志不保存完整私有源码、输入文档、语音或凭据。
- 删除与分享由用户明确操作，不自动发布到 GitHub Pages 或公共对象存储。
- 单文件和离线承诺必须通过无网络打开确认；可点击的来源链接只在用户主动点击时导航。
- 私有仓库不等于具有所引入第三方代码／素材的使用权；复用记录须保留来源、版本与许可。

## 16. 性能、成本、可访问性

以下为目标，需记录设备、资料规模、模型和输出模式后测量。

| 指标 | 初始目标 |
|---|---|
| 本地按钮可见反馈 | ≤ 100ms |
| 内置小模型重算 | 约定输入域内 P95 ≤ 200ms；长任务显示进度且可取消 |
| 重播 | 不调用模型、TTS 或外部执行环境 |
| Lab / slides 生成 | 基准主题、材料就绪时，目标 10 分钟内；外部研究另计 |
| 60–90 秒视频 | 指定演示设备目标 30 分钟内完成含渲染流程；必须实测 |
| 离线 HTML 体积 | 基准无音频主题目标 ≤ 5MB；超限说明原因 |
| 硬性运行边界 | 每案例设置步数、时间、内存与输出上限 |
| 自动修复 | 每阶段默认最多两轮，仍失败报告而非无限消耗 |

记录生成阶段耗时、模型用量、TTS 长度和渲染时间；价格按用户当前供应商配置估算，不写死未经核验的费用。

可访问性：键盘可操作、焦点可见、图表有文本等价说明、颜色不是唯一编码、支持减少动态效果。视频包含字幕；关闭声音不应失去核心信息。

## 17. 错误处理

| 错误 | 行为 |
|---|---|
| 来源不可访问 | 请求替代材料或缩小范围，不编造内容 |
| 关键前提错误 | 解释矛盾并调整问题，经确认继续 |
| 缺少可靠模型 | 提供证据型探索或 Story，明确不同能力 |
| 执行未授权 | 不运行；使用已提供轨迹或标记的模型 |
| 适配器超时 | 中止该案例并保存错误，不显示完成 |
| 输入超出模型范围 | 阻止运行并说明有效范围 |
| 结构／语义校验失败 | 局部修复，超过预算保留旧产物 |
| 来源冲突 | 并列呈现分歧和依据，不强行合并 |
| Pack 版本不匹配 | 拒绝无提示复用，允许显式迁移或重新生成 |
| TTS／视频失败 | 可保留已完成 slides，但清楚报告视频未完成 |
| 字体或资源不可嵌入 | 使用许可明确的替代并报告变更 |
| 分享涉及私有片段 | 显示材料清单，由用户决定，不自动公开 |

## 18. 验收标准

| ID | 场景 | 通过标准 |
|---|---|---|
| AC-01 | 从一般概念开始 | 不要求代码仓库，形成可理解 Brief |
| AC-02 | 从 repo 开始 | 记录版本、相关符号、范围和执行权限 |
| AC-03 | 主题不适合数值模拟 | 选择证据／比较范式，不生成虚构公式 |
| AC-04 | 输入含错误前提 | 澄清或纠正，不顺着错误生成结果 |
| AC-05 | 调整有效模型参数 | 结果真实重算，状态和解释同步变化 |
| AC-06 | 非法输入 | 明确提示，不静默截断 |
| AC-07 | 单步前后与重置 | 同一轨迹可恢复到相同状态 |
| AC-08 | 比较 A/B 案例 | 不同参数、引擎版本和模式清楚列出 |
| AC-09 | 预录真实轨迹模式 | 不提供伪实时输入能力 |
| AC-10 | 只有输入输出观察 | 不声称展示真实内部运行步骤 |
| AC-11 | 保存探索并交给 Story | 保留相同 Pack、输入和轨迹身份 |
| AC-12 | HTML slides 与视频 | 同一案例结果与 Lab 一致 |
| AC-13 | 确定性重渲染 | 固定输入、版本与种子后关键状态一致 |
| AC-14 | 源码或模型更新 | 依赖产物显示过期，不冒充最新 |
| AC-15 | Pack 中未知引用／资源 | 校验拒绝，报告定位信息 |
| AC-16 | 恶意文本／脚本输入 | 不执行，不注入可运行 HTML |
| AC-17 | 未授权执行／网络 | 不启动仓库程序或外部请求 |
| AC-18 | 无网络打开交付 HTML | 基础阅读、内置模型交互与回放正常 |
| AC-19 | 视频生成失败 | 清楚报告，不以别的格式冒充完成 |
| AC-20 | 渲染候选失败 | 不覆盖上一份有效产物 |
| AC-21 | 键盘与减少动画模式 | 主要操作可用，内容不因减弱动画丢失 |
| AC-22 | 许可与来源记录 | 复用项可追溯，限制明确，无未知素材静默打包 |

语义样例至少包括：重试可／不可重试错误、零次重试边界、复利无现金流排列不变、现金流时点差异、缺失证据、观点冲突和越界输入。

检查策略分为 Schema、主题不变量、已知结果对照、跨格式一致性和实际浏览器／视频视觉检查。AI 自审可辅助，但不能替代确定性检查或充当“真实性证明”。

## 19. 成功指标与用户验证

首轮目标是验证是否产生理解，而非页面数量或观看时长。

- 用户能否解释结果变化的原因，而不是只重复标题。
- 用户能否预测一个未演示过的合法输入的结果。
- 用户是否能区分真实执行、模型和示意。
- 用户能否从结论定位到依据，并识别一个未证实的主张。
- 分享者能否在不重复构建案例的情况下，从 Lab 生成可用 Story。

使用小规模成人试用，记录任务完成、误解点、修改次数和阶段耗时。对小样本只报告观察，不宣称统计显著的学习提升。

## 20. 实施计划与演示

假设 2–3 人、约 5 天、已获工具与模型权限；属于粗略计划，不是排期承诺。

| 阶段 | 产出 |
|---|---|
| 第 1 天 | Pack Schema、两个 Skill 骨架、主题路由、重试／复利样例与预期结果 |
| 第 2 天 | 引擎、轨迹、校验器、Lab 模板与离线打包 |
| 第 3 天 | 对照实验、探索导出、Story 提纲与 HTML slides |
| 第 4 天 | 一个受限视频模板、TTS／字幕、关键状态共享 |
| 第 5 天 | 来源与错误边界、跨格式一致性、视觉修复、演示排练 |

分工建议：一人负责 Pack 与行为，一人负责 Lab 与组件，一人负责 Story 与视频；共享 Schema 先稳定，避免分别发明事实模型。

演示建议：

1. 从“为什么两种平均涨幅对应不同结果”开始，展示纠正错误前提的能力。
2. 在 Lab 调整收益或现金流，单步查看结果。
3. 保存对照案例，生成 slides；展示基于同一案例准备的视频。
4. 切到重试代码主题，展示源码锚点与不同依据模式。
5. 展示一份证据型主题，说明 Aha 不把所有事情都伪装成模拟。

预渲染视频与缓存结果必须标识。所有展示材料使用公开、合成或明确批准的数据。

## 22. 完成定义

核心版本完成意味着：

一个聚焦问题可以形成有依据、明确边界的解释包；Lab 能进行真实有效的探索；Story 能用同一批案例生成 HTML slides 和受限短视频；产物持久保存，模式、来源和失败情况都不误导用户。

它不意味着已经能够准确模拟任何事情、自动证明任意代码的行为，或将任何输入无损转换为所有媒体格式。
