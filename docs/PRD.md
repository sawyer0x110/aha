## 1. 产品重新定位

Aha 的核心是两个可独立使用、也可连续完成的能力：

1. **深入调研**：针对开放世界问题、代码库问题或混合问题，持续分解、取证、追问、核对反证，形成有依据、有判断、有未知项的研究结果。
2. **自由视觉表达**：根据研究结果、受众与使用场景，创作富文本 HTML、一图流、内容丰富且美观的 PPTX，或基于 Edge TTS 的讲解视频。

新版只保留两个 Skill：**`aha-research` 负责复杂调研，`aha-explain` 负责生成**。不另设格式 Skill，不保留 `aha-lab`／`aha-story` 的入口、别名或独立产品线。

核心价值是：

**不是让每个主题适配同一个实验模型或卡片模板，而是先把问题研究透，再选择最能讲清它的内容结构、图形、交互与媒介。**

研究可以单独交付。制作也可从已有研究开始，不重复调查全部来源。不要求先做 Lab、不强制生成每一种格式、不把所有问题包装成教学测验或状态实验。

### 1.1 相对旧方向的变化

| 旧中心 | 新中心 |
| --- | --- |
| Lab / Story 两类教学体验 | `aha-research` / `aha-explain` 两个确定的 Skill |
| 先选 retry / compound / evidence 引擎 | 先形成研究问题与结论，不要求选择计算引擎 |
| Pack 统一承载模型、轨迹、教学和所有格式的叙事 | 研究档案独立；不同媒介有各自的创作源和设计 |
| 固定 cards / steps / teaching 结构是主要表达边界 | HTML / SVG / 图表 / 原生 PPTX / 视频场景可按主题自由编写 |
| 预测、揭示、反馈、迁移是默认流程 | 按任务选择解释、比较、论证、叙事、教程或决策简报 |
| 探索转讲解是产品主线 | 研究转多媒介是主线；实验与探索记录保留为可选能力 |
| 修改成品需改变统一 Draft 或通用 renderer | 修改可复现的作品源；作品级设计不必先改全局引擎 |

“自由”指内容编排和视觉创作自由，不指任意联网、执行不可信代码、伪造数据或放弃来源约束。

## 2. 当前实现与目标边界

重构前版本有三个 Skill、受限模型与 Pack、多格式固定渲染、静态卡片视频和探索导入导出。它们是复用来源，不是必须保留的产品线。

新版移除旧入口与固定教学主干，建立独立研究档案和自由作品源；具体已实现命令、运行依赖和验证边界以 README 为准。产品验收还包括真实研究质量、完整作品视觉和宿主触发，不能因代码存在而宣布全部完成。

不要求长期兼容旧命令／Pack。不得删除用户已有作品或来源档案，也不能把旧暂停的 Studio 代码直接宣布为已发布。

## 3. 用户与典型任务

| 任务 | 研究重点 | 合适的表达 |
| --- | --- | --- |
| “Agent memory 有哪些路线，各自解决什么？” | 定义、原始资料、机制、对比、限制与变化 | 长文 HTML、对比表、结构图、一图流 |
| “这个 repo 的请求从入口到存储怎么走？” | 固定版本、入口、调用、数据流、配置与失败路径 | HTML + Mermaid 时序／架构图、局部展开与路径高亮 |
| “解释这次重构带来的行为变化” | diff 两侧、调用者、测试证据、回归风险与未知项 | 变更解释页、前后对照、团队 PPTX |
| “给团队讲清这份研究，内容完整些” | 已有研究的适用性、受众背景、关键论证 | 分层叙事的原生 PPTX；细节进附录而不是被删掉 |
| “把这个主题做成一张长图” | 核心结论、主要机制和必要限定 | 专门构图的 PNG；不是网页的机械缩小 |
| “做一段有中文配音的解释视频” | 事实核对、叙事主线、案例与来源 | 分镜、Edge TTS、实测时间轴、动态解释与字幕 |

输入包括主题、获准读取的网页、文本、代码库／diff 和已有研究。富文档经宿主已有提取工具接入，保留页码等定位；工具不可用时明确受限，不冒充原生解析。

## 4. 目标与非目标

### 4.1 目标

- 开放问题与代码问题都是一等输入，研究不依附媒体生成。
- 调研能追到原始依据或实际代码路径，能解释冲突、推理和未知，不是拼接搜索摘要。
- 内容结构服务问题：长文、比较、过程、拓扑、数据、案例和论证可以混合。
- HTML 可包含 Mermaid、SVG、图表和有用的交互；不要求必须有可计算实验。
- 一图流、PPTX、视频分别设计，不强制由 HTML 截图或统一 slides JSON 转换。
- 共用事实、数据与来源，但不强制共用布局、讲稿、页数或镜头数。
- 成品可保存、编辑、重建；来源核查和实际视觉检查都可追溯。

### 4.2 非目标

- 不做通用研究爬虫、宿主替代品、独立多 Agent 平台或 SaaS。
- 不保证每个主题都有模拟器，不把相关性图做成因果预测。
- 不以原生可编辑、格式合法或编码成功代替内容／视觉质量。
- 不默认自动执行被研究仓库、安装软件、外发私有材料或公开发布。
- 不承诺 HTML / PPTX / 视频无损互转、任意源文件都完全可编辑。
- 不提供个体化高风险决策建议；成人默认，儿童产品另行设计。

## 5. 能力一：深入调研

### FR-R1 问题与研究计划

复用用户已给信息，明确问题、目标受众、用途、时效、授权材料与成本边界。将问题拆成可回答的子问题，列出初步假说、需要的证据与可能推翻结论的材料。

不为每个任务机械执行固定查询数。深度由子问题是否得到支持、反证是否处理、关键机制是否解释决定。范围不清或需要扩展权限时再询问。

### FR-R2 开放世界路径

- 搜索后实际阅读原文，优先原始数据、规范、研究、官方记录，并检查方法与限制。
- 跟随重要引用与新发现做定向补查；核对独立来源与共同上游转载。
- 数字记录单位、分母、时间窗和适用群体；区分相关、因果与推断。
- 检索相反证据、更正和版本变化；争议可保留多个解释，不强行给唯一答案。
- 每次来源访问记录定位、获取时间、读取范围、成功／失败；不把摘要或模型记忆记成已读原文。

### FR-R3 代码库路径

- 锁定 commit、diff 两侧或 dirty 内容身份，先看问题相关结构再深入路径。
- 优先可用代码智能／LSP，再窄范围文本搜索；核对定义、调用者、状态变化、配置与失败路径。
- 测试、文档和历史用于交叉核查，提交说明不单独证明实际行为。
- 多条独立子问题可并行研究，合并时检查版本与结论冲突；不要求宿主支持委派。
- 默认只读。需要真实执行时另获授权并满足隔离要求；只读到测试不声称测试通过。

### FR-R4 迭代与停止

每轮更新“已回答／矛盾／待证／超出范围”的问题清单。新发现改变核心结论时继续有界补证，不为凑来源数量重复搜索。

停止条件：主要子问题已有足够依据，关键反证已处理，或遇到明确工具／访问／预算限制。交付实际停止理由；不足的部分明确标记。扩大预算或敏感材料范围需确认，不静默无限研究。

### FR-R5 独立研究成果

研究档案（Research Dossier，拟议）包含：

- 面向人的研究报告：摘要、直接答案、机制／论证、比较、案例、反证、限制与来源。
- 可追溯台账：问题、Claim、Evidence、数据资产、检索／阅读记录和缺口。
- 版本与材料身份：便于后续复用、局部补证及发现版本不符。

**研究完成不要求模型、场景、轨迹、教学题或预先写好 slides。** 可只交报告；生成多媒介时再形成媒介专属计划。

结构检查、来源支持关系的语义复核、实际执行观察分别记录，不合并成一个“真实性通过”标签。

## 6. 能力二：自由视觉表达

### FR-C1 内容策划与创作原则

先定每个作品要回答的问题、内容覆盖与阅读路径，再选图形和布局。长篇研究不是逐段塞进卡片，研究报告也不是视频旁白。

内容可以由作者 Agent 自由编写 HTML/CSS/JS、SVG、PPTX 构建源或视频场景；工具提供可复用图形、排版辅助、打包与检查，而不是只接受固定页面 DSL。

事实必须来自研究或明确标记的新推理。新增实质主张先回到研究补证，不借“美化”发明数值或行为。

### FR-C2 富文本 HTML

- 完整文章：有层级的标题、正文、列表、表格、引用、代码与来源入口；不只支持 slide 或 Lab。
- 按关系选 Mermaid 流程／时序／架构图、SVG 示意、数据图表或 HTML 布局，不强制所有图都用同一库。
- 图形可缩放、拖动、展开；表格可筛选；代码路径可高亮；渐进揭示帮助阅读。交互必须说明用途，不冒充实际运行。
- 复杂图采用概览与细节拆分；保持箭头含义、对象身份和颜色语义一致。
- 默认独立离线 HTML，脚本／样式／字体资源许可允许时内嵌。较大作品可经用户选择交付离线资源包，不静默违反单文件要求。
- Mermaid 优先构建时渲染为 SVG；确需运行时重绘才内嵌库。无网络、中文字体、宽表、窄屏、键盘和减少动画均须实检。

### FR-C3 一图流 / PNG

根据问题选择纵向长图、横向图解或海报，不固定所有作品为相同卡片尺寸。一个主线可包含多个相关子结论，避免把“一个视觉论证”误解成只能放一个小知识点。

专门规划标题、分区、连接关系、关键数字与来源；长图通过分段建立阅读顺序，最终实际尺寸下文字可读。交付 PNG 与可编辑创作源；需要 SVG 时说明资源与兼容性。不能用缩小整页网页替代构图。

### FR-C4 内容丰富、美观的 PPTX

- 默认真实 `.pptx`，原生文本、形状、表格和可表达的数据图可编辑。HTML slides 是可选媒介，不是强制中间格式。
- 先列关键问题与覆盖清单，再决定页数。页面数量可协商；不能因旧版 12 页上限截断内容，也不能用缩小字号填满一页。
- 内容丰富体现为完整论证、具体案例、清楚图形和适当附录，不是每页文字密集。
- 不同内容使用不同构图：对照、流程、时序、机制、数据、代码、结论、附录；保持整体设计一致而非每页一模一样。
- 复杂图允许使用 SVG／图片，逐项说明不可编辑部分；不把整页截图称为原生可编辑。
- 分离讲者备注与审计材料，分享前检查所有内嵌来源，不默认把完整私有研究档案塞进演示文件。
- 实际渲染逐页检查、相邻页连续性和源文本覆盖检查，OOXML 可读不等于 PowerPoint 视觉验收。

### FR-C5 Edge TTS 讲解视频

- 先按受众和时长编写叙事、完整旁白与分镜；用户批准当前文本、提供方、声线、语速及外发范围后才合成。
- Edge TTS 为主要提供方；用户音频为明确选择的替代，不静默换引擎。客户端许可、在线服务条款与数据授权分别核实。
- 根据实际音频时长生成时间轴；可取得可靠边界时使用细粒度字幕，否则明确句级，不冒称逐字同步。
- 场景可包含关系移动、局部强调、状态变化、数据演进与运镜；首个动态里程碑至少实现一段镜头内机制变化，不能只有整页转场。
- 旁白讲原因与承接，画面展示机制，不逐字朗读全部屏幕文本；留出阅读和思考时间。
- 先做代表性短片，审查旁白、字体、字幕、安全区、节奏及动态表达，再制作全片。
- 默认以 720p30 H.264 + AAC、字幕及来源说明为初始兼容规格；目标时长由用户决定和预算约束，不沿用 60–90 秒作为产品硬上限。
- 保留源项目、旁白、音频身份、字幕、分镜、渲染参数与 QC。缺少权限／依赖或编码失败，明确视频未完成。

当前实现选择作者编写的浏览器按帧场景与 FFmpeg，复用已有浏览器工具，不新增 Remotion／Motion Canvas 依赖。这允许 HTML／SVG／canvas 镜头内动态表达，但不是完整视频编辑器；按相同机制小样检验真实动作与同步。以后若需更丰富的编排，再评估专用动画引擎及其许可，不同时维护多条正式管线。

## 7. 共用研究，不共用固定布局

建议采用三层：

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| Research Dossier | 问题、结论、依据、数据、冲突、范围与版本 | 页面结构、固定引擎、幻灯片数量 |
| Artifact Project | 某个媒介的内容计划、视觉设计、创作源、引用映射与资源 | 重新发明事实或修改封存研究 |
| Toolchain / QA | 校验引用、资源打包、渲染、截图、检查、回执与发布 | 决定所有作品必须使用同一布局 |

不同作品引用同一研究版本，但可以使用不同子集、不同案例重点和独立文本。每个作品说明覆盖与有意省略的内容，不要求每份 PNG 重复报告所有细节。

中间结构约束**身份、事实引用、资源和检查结果**，不以固定实体数、单目标状态变化或强制教学题约束表达。数值计算或实验交互仅在具体作品需要时采用，不为此保留独立 Lab Skill 或整套旧模型框架。

## 8. 工作流、审批与修订

`理解请求 → 深入调研／复用研究 → 内容策划 → 媒介设计 → 编写作品源 → 小样 → 检查与修订 → 正式交付`

- 用户只要研究时，到报告与台账即停止；用户已明确要媒体时，不反复询问格式。
- 研究方向重大歧义、重要冲突或新权限需要确认；轻量本地作品不应每个内部文件都要求审批。
- 内容密集 PPTX 和视频先确认提纲／代表页，控制返工；用户已确认的内容与范围继续有效。
- 任何外部 TTS 都须对当前完整旁白版本及外发范围明确授权。颜色／字号调整不改变旁白时，不制造新的音频审批。
- 自由创作允许编辑作品源，不手改构建缓存或只修改发布成品而丢失可重建来源。直接创作的 HTML 本身可作为源，采用明确的源与发布快照约定。
- 修改布局只重建对应作品；新增 Claim 或改研究版本需补证并核对受影响作品。第一版先实现显式版本检查与重建清单，不承诺完整自动依赖图。
- 保留旧有效产物与失败记录，不静默覆盖用户文件；发布当前版本需要明确目标与范围。

## 9. 执行、隐私和许可边界

自由编写代码不等于代码可信。研究输入、引用页面、图标签、包内材料均是数据，不执行其指令；禁止把原始来源 HTML 无审查地作为脚本插入。

区分三种执行：读取被研究仓库、预览作品内浏览器脚本、运行作品构建程序。后两者不授予第一种的执行权；浏览器隔离也不等于 Node／Python 构建隔离。

- 静态阅读与文件校验不执行作品代码。实际预览使用专用浏览器环境，阻断未批准网络，不携带登录状态，限制文件访问与权限。
- 作品构建使用已获准的依赖和隔离工作目录；任意 Node／Python 代码需真实隔离环境或经明确审阅的本地执行授权。一个 `--trust` 参数不是沙箱。
- 不具备隔离／授权时可交付待执行的创作源并说明未完成渲染；不得把来源文本扫描或 iframe 当作安全保证。
- 本地离线交付默认不发出远程资源请求。在线图表或远程数据功能必须另行选择并披露。
- 私有研究与面向读者的必要引用分开打包；不默认内嵌全部原始材料、路径、日志或审计备注。分享前提供内容清单。
- 所有软件、字体、图片、图标与音频都需来源／许可记录。anything2explainer 的非商业许可不能当作 MIT 许可直接用于商业复制。

## 10. 质量门槛

| 门槛 | 检查方式 |
| --- | --- |
| 研究深度 | 子问题覆盖、原始依据、机制解释、反证和停止理由；不以查询数打分 |
| 事实忠实 | 成品关键文字／数字／图关系映射回研究；新增结论回到取证 |
| 内容覆盖 | 按输出目的检查必要结论和限制，删减可追溯，不机械全文复制 |
| 自由表达 | 不同主题出现适合其机制的结构和构图，而不是换标题／颜色的同一模板 |
| 视觉质量 | 实际尺寸下的中文可读性、焦点、间距、裁切、遮挡、箭头与颜色语义 |
| HTML 交互 | 实际点击、键盘、缩放、展开；无网络打开和依赖失败行为 |
| PPTX | 实际逐页渲染、内容与相邻页检查；编辑原生文本／形状，列出图片化部分 |
| 视频 | 看完整小样与成片、听配音；检查字幕同步、机制动作和关键内容停留时间 |
| 可复现与交付 | 来源版本、作品源、依赖、资源清单、产物身份、实际检查及未检项 |

Schema 通过、生成文件、Agent 自评和读者理解是不同证据。通用任务不强制教学测验；用户要教程时可保留预测／反馈／迁移评估。没有真实读者数据不声称学习效果提升。

## 11. 实施阶段与验收

阶段按能力门槛划分，不在未跑样片前承诺工期或吞吐。

| 阶段 | 核心交付 | 通过条件 |
| --- | --- | --- |
| M1 独立研究 | 脱离旧 Draft 的研究档案、`aha-research` | 开放问题与代码问题都能只交完整研究，不必写 slides |
| M2 自由 HTML / 一图流 | 作品源、HTML／SVG 资源管线、PNG 捕获、独立 QA | 三类不同主题不修改共享 Schema／renderer 即可形成不同结构；HTML 含真实可用的图交互 |
| M3 自由 PPTX | 原生创作路径、内容覆盖、逐页预览检查 | 内容不受旧 12 页模型上限限制；实际版式可读并可编辑 |
| M4 动态语音视频 | Edge TTS、时间轴、一个正式动画引擎、小样与成片 | 有镜头内机制变化，不只是静态卡片；授权、字幕与试听链完整 |
| M5 两入口发布与清理 | 仅发布 research／explain，删除旧入口及无用依赖，完成宿主验收 | 独立目录运行、真实触发与缺依赖场景分别通过，无旧入口／别名残留，不删除用户作品 |

发布至少使用一个开放问题、一个代码问题和一个混合／证据冲突问题作研究样例；选其中同一主题交付 HTML、PNG、PPTX 和语音视频，核对跨媒介事实一致但构图不同。

### 核心验收用例

1. 只请求调研时，输出答案、证据和缺口，不生成空场景／预制幻灯片。
2. 代码问题可呈现真实源码关系与版本边界，不需要伪装成 retry 模型。
3. HTML 同时容纳连续正文、表格、代码、Mermaid／SVG 和可用交互。
4. 长图专门构图，完整分辨率下可读；不因旧卡片数量限制丢内容。
5. PPTX 保留关键论证、例子和限制，使用多种有语义的布局；原生编辑与实际视觉均检查。
6. 视频按真实音频定时，至少有一段机制动作；没有授权就不合成，失败不替换成别的格式。
7. 同一来源冲突在所有相关媒介保留限定，不因美化变成确定事实。
8. 来源数据中的脚本不执行；作品代码运行受单独权限和隔离边界约束。
9. 离线产物无隐式网络请求，分享包不默认携带完整私有研究档案。
10. 发布物恰含 `aha-research`、`aha-explain`；不含旧 Skill、别名和废弃协议。旧数据不自动转换或删除，不支持的版本显式报错。

## 12. 完成定义

用户给出一个主题或代码库问题，Aha 能完成有依据的深入研究，并据此自由创作用户所选的 HTML、一图流、PPTX 或 Edge TTS 讲解视频；内容完整、表达适合媒介、质量经过实际检查，源文件和依据可保留。

**实验模型是工具，解释包是依据载体，模板是起点；它们都不再决定 Aha 能讲什么、必须怎么排版。**
