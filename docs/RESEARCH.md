# Aha 复杂调研协议

`aha-research` 是独立能力。研究不要求引擎、实验、教学题或幻灯片；`aha-explain` 复用同一份研究档案与工作法，不维护第二套简化调查流程。

## 问题驱动的多轮研究

1. 聚焦问题、受众用途、版本／时效、授权范围与预算，列出关键子问题。
2. 为每个子问题提出待证解释，明确需要的支持与可能推翻它的证据。
3. 实际取证，记录读取范围、材料身份和成功／失败，不把计划动作写成已执行。
4. 综合当前答案、比较独立来源、核对反证和数字口径，更新问题状态。
5. 根据缺口追问与补查；重大冲突改变结论，不能只在末尾加免责声明。
6. 核对关键主张与来源上下文，交付报告、台账、未解决问题与停止理由。

不以固定查询数或来源数宣称“深入”。预算防止无限研究；充分回答可提前结束，达到上限要明确缺口，扩大权限或显著成本前确认。

## 开放世界问题

- 阅读原始研究、规范、数据或官方记录，继续核对方法、假设与利益相关性。
- 记录真实标题、URL、发表／更新日期、获取时间和读取段落，区分摘要与正文。
- 检查数值的单位、分母、时间窗、地区和群体；相关不等于因果。
- 搜索反例、相反结果、更正与版本差异；共同上游转载不是独立佐证。
- 不能访问的付费墙、登录内容或失效来源保留未知，不补写原文。

## 代码库与变更问题

- 固定 commit、diff 两侧和工作区修改身份；dirty 内容不能冒充 HEAD。
- 优先可用代码智能／LSP，再按文件、符号和语言窄搜索。
- 追踪入口、调用者、状态／数据流、配置分支、失败路径和终止条件。
- 核对测试、文档与历史；测试源码和提交说明不是实际运行证明。
- 断言定位到版本、文件、符号、行与内容身份；证据不足时明确范围。
- 默认不运行被研究仓库。执行须有独立授权和合适隔离，不把阅读许可当执行许可。

混合问题同时保留两种来源。公开产品说明不能证明本地实现已具备相同行为；一次实测也不能证明所有并发路径或线上性能。

## 独立研究档案

`research-init` 创建需要作者填充的草案，不执行搜索。完整字段以构建随附的 `research-draft.schema.json` 为准，研究通常包括：

| 内容 | 用途 |
| --- | --- |
| 问题与范围 | 明确回答什么、不回答什么 |
| 报告 | 直接答案、机制、论证、比较、案例、反证与限制 |
| 子问题 | 已回答／部分回答／未知及对应结论 |
| Claims | 可追溯主张、类型、依据与适用限定 |
| Evidence | 实际来源定位、摘要、版本／日期与必要内容身份 |
| 日志 | 实际查询、阅读、失败和结果，不编造工具调用 |
| 缺口与停止理由 | 未核实部分和最小补证动作 |

草案不必伪造搜索：仅基于用户提供材料时说明 `provided` 范围和实际阅读，不能声称独立公开调查。占位草案不能当作已完成研究建档。

`research-check` 只检查结构、引用、覆盖与必要身份。`research-build` 写入新的研究目录，`research-validate` 核对快照与报告一致性；它们不会访问网页或认证事实。

研究过程中使用 `research-check <draft.json> --draft`：结构正确的未完成草稿返回 `draft-checked`、`ready: false` 和待补事项，不写快照、不生成哈希、不伪造交付完成。尚未填写的报告、支持、覆盖、缺口及成功阅读记录可作为待补项；无效引用、相互矛盾的显式链接、重复 ID、错误日期／来源元数据／日志和哈希不匹配仍失败。普通检查与构建保留严格完成条件。

在首次编写或排错时按需读取[完整虚构案例](../skills/shared/references/research-example.md)，观察一条纠正材料如何改变初步结论、保留反证并明确剩余缺口。研究语言按研究请求选择，不受图片／PPT／视频的英文默认值影响。

## 研究与表达分开

`aha-explain` 先检查已有研究的时效、问题覆盖和材料权限，仅补缺口。为每个媒介设计独立内容覆盖和引用映射，允许有理由地省略细节，但不能删除会改变结论的条件。

HTML／PNG／PPTX／视频共用事实，不要求相同文字或布局。报告不是逐页大纲，也不是视频旁白。预测、反馈和迁移题仅在教程确有需要时使用。

新增事实或推理要回到研究；纯样式改动不重新搜索。研究版本变化后核对作品身份和引用，不把旧来源伪装成最新。

## 成品事实核查

抽取成品中的关键断言、数值、时间、代码行为和图关系，逐条回查研究与实际来源。分开记录：

- 来源支持，且版本和限定正确。
- 表达需要修正，或省略了重要条件。
- 证据不足／冲突，无法得出确定结论。
- 当前工具或授权无法核查。

引用存在不等于支持关系成立，哈希正确不等于材料真实。语义复核属于 Agent／人工研究工作，不以机器结构检查代替；实际执行观察另记环境和输入。

## 交付与授权

报告、完整研究档案和面向读者的作品分开。默认不将完整私有资料、路径、检索日志或备注嵌入分享文件；正文保留必要引用和自然语言限定。

用户已明确要求从研究到媒体时，不重复询问格式或每个内部文件；重要范围变化、事实冲突、代码执行和外部 TTS 仍需对应授权。新旁白必须展示完整文本、提供方与声音参数，不能只让用户批准一个 hash。

研究质量、作品视觉、运行检查与真实读者理解分别记录。未观察的行为、未运行的测试、未试听的音频不写成通过。
