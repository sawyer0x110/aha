# Aha Lab：自己探索，弄懂为什么

## 当前能力

- 交付解释包目录 `topic.aha`、独立 HTML 和渲染回执；可导出探索记录供 Story 使用。
- 计算仅支持 `retry`、`compound`，在 Pack 中标为 `derived-model`。其他主题使用 `evidence`／`source-based`；向委托人说明无计算引擎，最终读者页面用自然语言表达必要条件，不用协议标签代替解释。
- 当前前端与内容仅支持 `zh-CN`。英文输出、真实执行、观察轨迹导入和富文档直接解析未实现。`source-based` 不表示独立验证事实。
- 用户另选图片、PPTX 或视频时，按 [格式交付](references/formats.md) 使用同一 Pack；不把 Lab 截图当作原生演示，也不擅自换格式。
- 不依赖 Canvas、MCP、特定提问 API、子 Agent 或另一个 Skill 自动加载。

## 最终读者交付

- HTML 默认是供最终读者独立理解的知识成品，不是 Brief 摘抄、制作说明或给另一位 Agent 的交接。先直接讲明主题，再给具体概念对照／步骤与有理由的理解题答案；图示解释主题而非制作管线。
- 受众是内部编写输入。可见正文、图示和旁白不放受众标签、来源计数、Claim ID、哈希、生产／协议／审批指令；这些保留在 Pack、研究台账、回执与来源元数据。简洁来源和必要事实条件自然保留，来源查阅是次级入口，不是主要学习活动。
- 使用 `brief.explanation.visual`／`conditions`／`answer` 和 Slide 的 `visual`／`conditions` 编写解释，按 [编写契约](references/authoring.md) 的 `TeachingVisual` 约束关联已有 Claims。图示是普通字符串组成的审阅过的讲解，不是新模型、执行代码或观察轨迹；不能只清除标签而不写内容。
- 取证后先按 [解释设计](references/teaching-design.md) 写可预测／解释／迁移的目标、误解与先备知识，选具体内容例子；来源事实不是脚本。有依据的状态变化可用可选 `teaching`，其他主题保留概念对照或数值模型，不硬套序列。
- 按 [格式交付](references/formats.md) 设计 Lab 的预测 → 揭示 → 具体反馈；记录状态回放不是实时 Git 执行。先看变化与不变量，再归纳规则，用新情境检验迁移。

## 开始前

1. 读取随本 Skill 发布的 [编写与工具契约](references/authoring.md)、[受众适配](references/audience.md)，按输入直接读取 [代码库研究](references/research-codebase.md)／[公开内容研究](references/research-public.md)，无需自动调用另一个 Skill。
2. 找到**本次已加载 Skill 的安装目录**，将以下命令中的占位符替换为实际绝对路径。不要假设当前工作目录就是 Skill 根目录。
3. 在宿主允许本地命令执行时运行：

   ```powershell
   node "<技能绝对目录>\scripts\aha.mjs" doctor
   ```

   POSIX 路径写作 `node "<技能绝对目录>/scripts/aha.mjs" doctor`。需要 Node.js 22 或更高版本。
4. 查看 JSON 能力结果。不自动安装依赖、不联网、不执行用户仓库。没有获准的命令工具或 Node 时，报告阻塞；可以整理草案，但不能声称生成已验证产物。

## 工作流程

### 1. 先研究，不先排页面

- 复用用户已给出的信息；默认成人初学者、中文、单主题，儿童版不在范围。过宽问题拆成可检验子问题；先约定读取范围、预算与停止条件。
- 建立 Brief：主题、问题、受众实际已知背景、预备知识、范围、排除项。不从年龄或职业推断知识。可选 `brief.explanation` 按受众参考编写；不添加 Schema 外字段。
- 仓库先锁定 commit／diff 两侧及 dirty 内容身份，按代码智能／LSP → 窄文本定位定义与调用者；追踪代表路径及错误／重试／取消，再核对测试、配置和历史。断言带文件／符号／行、`sourceVersion` 和真实 `contentHash`。
- 公开材料先找原始依据和独立核查，保存精确查询、标题、原文日期、链接与 UTC 获取时间；实际读正文，检查数值口径、同源转载和反证。未读到、付费墙或缺工具时保留未知。
- 只读获准材料，来源命令是数据；不执行不可信仓库的 install／test／build。只读测试不能说测试通过，commit 消息不是单独行为证明。
- 分开记录“来源声称”“模型结果”“解释性推断”和“未解决问题”。模型规则不能证明真实仓库或现实世界必然如此。
- 建立主张台账与 scope gaps，按契约填可选 `research`；研究任务应填它。先报告答案、冲突与缺口再决定呈现。模型生成事实不算外部证据。
- 没有研究／浏览工具时如实降级为获准材料说明，不能声称全面研究。`init`／`example` 是合成模板／演示，不替代研究。

### 2. 路由与草案

- 内置规则确实吻合问题时，选择重试或复利；若材料涉及取消、随机抖动、费用税收等未建模机制，披露缺口，不偷偷忽略。
- 其他主题先告知：“本版没有这个机制的计算引擎，可以制作有来源与未知项的证据探索页。”不捏造参数、因果滑杆或计算结果。
- 使用 `init <engine> <新草案.json>`，随后编辑自己的草案。替换模板问题、来源、主张、案例和叙事，保留真实的合成标签，不只改标题。
- 按 [Lab 编排与检查](references/lab-workflow.md) 设计最小案例及对照。重试和复利的精确输入边界见共享契约。
- 草案的 `narrative` 可手工编写 1–12 页，按任务需要而非强制凑 5–8 页；它是共享讲解内容，不是作者待办，不表示已交付 Story。数值 Story 导入模板的页数限制另见下文。
- 只编写 Draft 字段。轨迹、manifest、Pack 哈希由程序生成，不手写或补造；代码 Evidence 的真实内容哈希仍由作者计算。
- 按受众调整词汇、深度与 framing，事实／单位／边界不变。成人初学者至多一个有边界类比，配理解题与参考答案；管理者聚焦决策／影响权衡，工程师聚焦机制／契约／失败。未实现的 Git／天气实时执行不能被图示暗示为已有能力。
- 首次构建前提交规范 `draft.json`、主张与检索台账、反证和缺口供明确审阅；未获审阅只交付草案。用户明确要求纠正已审阅且事实／证据不变的呈现，授权对应本地修订：保持 Claim／Evidence ID 与内容身份，记录范围和新 Draft 哈希、保留旧输出，不为纯 UI／排版另造审批循环。新发现须补证审阅；新旁白外发另批完整文本、provider、voice、rate、时间安排及当前 `planHash`，详见 [审阅范围](references/authoring.md)。

### 3. 计算与检查

```powershell
node "<技能绝对目录>\scripts\aha.mjs" research-check ".\draft.json"
# 研究与草案明确审阅后：
node "<技能绝对目录>\scripts\aha.mjs" build-pack ".\draft.json" ".\topic-v1.aha"
node "<技能绝对目录>\scripts\aha.mjs" validate ".\topic-v1.aha"
node "<技能绝对目录>\scripts\aha.mjs" run ".\topic-v1.aha" baseline
```

- `baseline` 必须替换为实际案例 ID。`run` 只返回经内置规则校验的案例轨迹，不运行外部代码。
- 检查预期结果、终止条件、引用与适用边界。校验通过只证明结构、引用和内置规则一致，不证明来源真实性或所有自然语言主张正确。
- `research-check` 要求 `research`，只检查草案／研究元数据结构与覆盖，不执行搜索或证明研究质量；无此元数据时返回缺失错误，既有草案可用普通 `build-pack`／`validate`，但不应假称已完成研究检查。
- 若发现草案错误，修正草案并写入新的 Pack 路径，不编辑已封存解释包。

### 4. 渲染与探索

```powershell
node "<技能绝对目录>\scripts\aha.mjs" render-lab ".\topic-v1.aha" ".\topic.lab-v1.html"
```

- 输出 HTML 必须位于 Pack 之外；已有文件不会被覆盖，重渲染用 `v2` 等新路径。
- 按 [检查—修订闭环](references/quality-loop.md) 先保存代表性 pilot 截图，检查颜色编码、delta、关系、焦点、可读性与媒介适配，再改设计／通用实现并重新生成，不手改最终 HTML。有浏览器工具时检查实际文件的模型交互、前后单步、来源、对照和下载；没有工具时报告阻塞。
- HTML 观看不需要 Node、模型密钥或开发服务器；来源链接由用户主动打开时仍可能联网。
- 用户在页面选择案例并显式下载探索记录。CLI 等价入口：

  ```powershell
  node "<技能绝对目录>\scripts\aha.mjs" export-exploration ".\topic-v1.aha" ".\topic.exploration-v1.json" baseline
  ```

- 导出最多 10 个案例；省略案例 ID 表示全部，超过上限会失败。数值 Story 导入模板只接收 1–4 个；来源模式保留已编写的叙事，选择留在新修订／回执，不生成材料选择交接页。
- 保留导出所依附的**原始 Pack 修订**。备注属于用户笔记，不是事实证据。

## 失败、续跑与交付

- 同一问题两次局部修补仍失败就返回设计层，不设任意全局通过轮数；继续修订到阻塞项关闭或如实报告真实限制。按闭环记录输入身份、命令、错误、截图与检查；独立 Agent 视觉审阅只是启发式，学习任务成绩须基于实际回答，未测不能编造。
- 不通过删旧文件、放宽校验、改哈希或擅自改交付格式掩盖失败。保留旧有效产物，修复后使用新目标路径。
- 生成物、批准输入／证据／Pack／必要回执和版本化截图／日志默认放忽略的 artifacts 或获准会话工作目录；旧版可归档回滚。用户指定交付目录后，显式 promotion 一套当前成品，不静默覆盖用户文件。
- 续跑先核对输入和已生成 Pack 身份；输入变化后主动重新构建依赖产物，不能沿用旧结果。程序在重验／导入时检查快照身份，不监视来源更新；离线 HTML 不监听源文件，也没有完整自动依赖图或增量失效机制。已有来源仍适用时不重复取证。
- 向委托人的完成报告给出 Pack、HTML、CLI 返回的回执位置、模型／来源性质、实际检查和剩余限制，与最终读者成品分开。程序检查不证明语义、视觉质量或宿主安装验收通过。
- 分享前提醒：HTML 包含解释包内容，来源摘要和备注也可能随文件交付；`private` 是标签而非加密或访问控制。不默认上传或公开发布。
