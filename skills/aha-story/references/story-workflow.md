# Story 叙事与交接

## 研究与受众先于版式

直接使用 [代码库研究](research-codebase.md)／[公开内容研究](research-public.md)，不等待另一个 Skill 自动取证。叙事与研究共同进入 Draft，具体问题、身份、原始材料、代表路径／反证、主张台账和缺口首次经明确审阅后才建包；不是先审批空骨架、再未经审阅补入事实。

按 [受众适配](audience.md) 选择词汇、类比边界、深度与 framing；管理者的决策、工程师的机制、初学者的理解题可以不同，事实／单位／限制不能变。`brief.explanation` 不是外部证据；不能为讲得顺而新增收益、耗时或源码行为。已审阅且事实／证据不变的呈现纠正由用户明确请求授权，按 [审阅范围](authoring.md) 记录范围与新 Draft 哈希、保留旧输出；不为纯 UI 改动重复审批，新发现与外部 TTS 不在此授权内。

## 按理解任务编排，不固定六页

按 [解释设计](teaching-design.md) 先写读者的预测／解释／迁移目标、误解与先备知识。下面是可按主题合并／拆分的解释职责，不是要求每项占一页：

1. **问题／预测**：具体内容与最可能的错误预测，而非泛泛“今天学习什么”。
2. **操作／变化**：展示具体案例中的目标 delta、关系及未变对象，配适用条件；数值状态来自保存的模型输出。
3. **机制／规则**：先经历对照再归纳原因，不用术语表代替机制。
4. **迁移／收束**：不同情境的问题、判断与理由，再收束为可复用规则。答案不要在提出预测前泄露。

手工编写总页数为 1–12，不强制 5–8 页；数值导入模板限制另见下文。每页一个重点，不把“请补上案例”等指令当页面正文。正文直接对最终读者解释，补充教学解释可放 Pack 的 `narrative.slides[].notes`，但答案与关键条件不能只能靠另一位作者补讲。`claimIds` 供内部关联，不打印到页面。`narrative.slides[].visual`／`conditions` 与 Brief 同形状；有依据的状态例子可用 teaching 与 `Slide.scene`，精确限制见共享契约。

按 [每种媒介设计](formats.md) 把事实重新构图：hook 聚焦矛盾，transition 放大变化，mechanism 展示方向／不变量，transfer 先呈新题，takeaway 收束规则。HTML slides／PPTX 不能每页都是同一三列卡片；PNG 单独选择一个视觉论证，视频另写分镜／旁白／视觉分工，不逐字读卡片。

所有格式默认供最终读者独立使用。受众留作内部输入；可见正文、图示、Pack 讲解备注与旁白不含来源计数、Claim ID、哈希、“原解释包讲解要点”或生产／审批／协议指令。审计信息在 Pack、研究台账、回执与来源元数据保留。必要事实条件自然说明，简洁来源作为次级入口；不能以选来源代替概念理解，也不能为清爽删掉反证。

原生 PPTX 审计备注与内嵌 Pack 有意保留完整来源身份和研究元数据，供追溯；它们与读者讲解字段不同，不应全部删除审计信息。TTS 使用 Pack 的 `narrative.slides[].notes` 准备旁白，原生 PPTX 审计备注不会送入 TTS。两类备注都可能随文件交付，分享前分别审查。

## 场景与事件引用

- `scenarioId` 指向当前 Pack 中存在的场景。引用 `eventStep` 时必须带场景 ID。
- `eventStep: 0` 选择初态；之后的整数不能超过该场景事件数。它不是毫秒数或动画帧。
- 可以省略步骤来呈现案例结果；要强调具体分支，先查看 `run` 的真实事件序列再选择。
- 没有计算轨迹的证据模式不捏造中间状态。可以按已审阅 Claims 写概念对照或操作步骤，`visual` 只是普通字符串，不是新模型、可执行代码或观察轨迹；有明确记录／来源依据才写 teaching 状态及 scene，不能把阅读顺序称作实验结果，也不暗示实时 Git／天气模拟。
- 页面状态使用 Pack 数据；正文中的金额和次数仍需作者核对，程序不会理解并纠正所有自然语言数字。

## 探索导入后的检查

探索格式与导出允许 1–10 个选定案例；数值 `import-exploration` 的 5–8 页模板接收 1–4 个，超过 4 个返回 `STORY_CASE_LIMIT` 且不创建 Pack。重新选择或分批导出，不静默遗漏；A/B 两案例不受影响。来源模式不按来源选择数重写页面，而是保留原本已编写的 `narrative`、图示与条件；选择仍保留在新修订和导入记录。

成功导入新增案例、增加修订号并记录父哈希；这不等于自动完成受众适配或叙事编辑。

主 HTML、卡片／PNG、原生 PPTX 都从实际导入的 Pack 渲染，产物／回执应绑定该修订；不能退回源 Pack 渲染来掩盖导入后的内容问题。原叙事保留与新修订身份必须同时成立。

检查原问题是否仍合适、案例比较是否公平、原有 Claim 是否真的适用于新的参数。输入域合法与轨迹一致，不能证明所有旧主张在新案例下仍成立。

导入笔记保存在记录中，不进入旁白或主张。不得将“原解释包讲解要点”、来源计数或选择交接说明替代已写好的主题解释。若需修订内容，按 [共享契约](authoring.md) 整理新 Draft 并应用对应审阅范围，再构建新快照；当前没有通用保留修订链的叙事编辑命令。

原始 Pack 不匹配、模型版本不兼容、轨迹不一致或模式不支持时停止导入，不能通过手动替换身份来“修复”。

## 离线讲解页

内嵌 reveal 核心，不依赖 CDN。备注在同页查看，不承诺离线弹出演讲者窗口。浏览器直接打开交付文件；未实际检查就不能宣称键盘、全屏、窄屏或视觉布局验收通过。

按 [检查—修订闭环](quality-loop.md) 先保存代表性机制页／迁移页 pilot 截图，查颜色编码、delta、关系、焦点、可读性与媒介适配。先修 Draft／Skill／通用实现再重新生成，不手改最终 HTML／PPTX；同一问题两次局部修补仍失败就返回设计，不设任意全局通过轮数。独立 Agent 视觉审阅是启发式，实际读者任务成绩另记，没测不编造。生成物、来源记录、迭代／截图／日志默认放忽略的 artifacts 或获准会话目录，只向用户指定的交付目录显式推广一套当前成品，旧输出可归档回滚。

分享前审查全部内嵌数据，尤其演讲备注和私有来源定位。浏览器中折叠／隐藏的内容并非保密内容。

## 图片、原生 PPTX 与语音视频

按 [格式交付](formats.md) 选择实际命令和可选依赖。图片／PPTX 从 Pack 的文字、来源与保存状态适配，不把整页 Lab 截图作为可编辑原生内容；交付后检查真实文件。

视频使用 `prepare-video` → 展示只读计划的完整旁白／provider／voice／rate／时间安排 → 人工批准当前 `planHash` 与该版本外发 → `synthesize` → 实测音频／pilot → 正式 `render-video` 与 QC。已选 Edge TTS 或本地呈现纠正不代表新旁白获授权；修改计划必须重新审阅。只向已选提供方发送已确认旁白，不默认外发私有 Pack；provider／voice／hash 记录在审阅材料／回执，不印在教学画面，不记录秘密。Pilot 的实际命令复用与独立审批见格式参考。

缺少浏览器、FFmpeg、TTS 依赖或授权时停止并报告；未经用户改选不能以 HTML 代替视频。编码成功不等于画面、字幕或音质验收；未观看／试听就写未执行。
