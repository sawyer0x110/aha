# 从已审阅依据到多格式交付

优先顺序：研究与读者解释 Draft → 明确审阅 → Pack → 用户选择的格式。格式不是证据，渲染成功不证明研究正确。已审阅且事实／证据不变的呈现纠正遵循 [编写契约的审阅范围](authoring.md)：用户的明确请求授权对应本地修改，不为纯 UI／排版制造重复审批；记录范围、新 Draft 哈希与旧输出。新发现和新旁白外发不属于此授权。所有命令接在可信的 `node "<技能绝对目录>\scripts\aha.mjs"` 后。

## 最终读者成品，不是制作交接

- HTML、PNG、PPTX、MP4 默认给最终读者：直接解释主题，具体对照／步骤帮助理解，再给理解题及有理由的答案。不是委托人的 Brief 摘抄，也不是下一位 Agent 的任务清单。
- `TeachingVisual` 通过 `brief.explanation.visual` 或 Slide 的 `visual` 关联已有 Claims；配自然语言 `conditions`、Brief 的 `answer`。它是普通字符串组成的审阅过的讲解，不是 HTML／代码执行、新模型或观察轨迹。图示解释主题而非制作管线，精确 Schema 限制见共享契约。
- 受众是内部输入；可见正文、图卡、幻灯片、Pack `narrative.slides[].notes` 的讲解文字和旁白不含来源计数、Claim ID、哈希、研究／生产／协议／审批指令。这些信息保留在 Pack、研究台账、回执和来源元数据，不因输出简洁而删除审计记录。
- 来源查阅是次级入口，不是主要学习活动；保留简洁来源和会改变理解的事实条件。例如假设天气概率不是实时预报，时间窗／降水阈值依产品定义；Git 普通 add、add -p、commit -a 不可混为一种行为。使用已审阅对应主张，不暗示页面能实时执行 Git／天气模拟。
- 不只是去掉标签：实际输出必须能读懂一个关系、对照或步骤并核对答案。PNG 是本地浏览器渲染专用卡片，不是图像生成 API；视频未实际生成时不得称已交付。

原生 PPTX 审计备注与内嵌 Pack 有意保留完整来源身份和研究元数据，供追溯，不属于教学画面；它们不是 Pack 的 `narrative.slides[].notes`。TTS 从后者的读者讲解文字准备旁白，原生 PPTX 审计备注不会送入 TTS。不要将“旁白不含审计信息”误解为“全部 PPTX 备注都必须去审计化”；分享前仍审查文件中的审计备注与内嵌数据。

## 每种媒介单独设计，不能只换容器

先按 [解释设计](teaching-design.md) 确定误解、先备知识、具体案例、预测／解释／迁移任务。事实复用，构图不照搬：在作者工作记录中为所选媒介写“读者这一刻要看什么／做什么，什么由画面表达、什么由文字解释”，再编写 Draft 的相应字段。

| 媒介 | 必须设计的学习动作与视觉职责 |
| --- | --- |
| PNG／卡片 | **一个视觉论证**：一个问题或结论作 headline，中心展示具体内容的差异／关系，summary 只补语境，takeaway 收束规则。teaching.card 的 transitionIds 只选支撑论证的操作；保留关键条件与简洁来源，不把 glossary、完整计划、所有例外和理解题全文同时堆满 |
| Lab | **预测 → 揭示 → 具体反馈**：先给初态和操作，隐藏正确结果供选择；揭示目标变化与未变部分，按每个选择解释原因，再给不同情境的迁移。teaching 是记录状态回放，不是真实 Git 执行；数值引擎才按其规则重算，不用来源切换冒充实验 |
| HTML slides | 用 scene 目标改变构图：hook 一个冲突／问题；transition 放大前后 delta；mechanism 强调操作方向、关系和不变量；transfer 先出新题；takeaway 一条可复用规则。安排阅读／揭示顺序与留白，不是每页标题加相同三列卡 |
| 原生 PPTX | 与 HTML 共享事实和场景目标，但重新分配画布层级、阅读距离、标题／内容比例和原生形状关系。用位置／连线／标签表达复制或影响，维持对象身份，不把每页改色当不同设计；实际演示中检查可编辑性、中文字号与遮挡 |
| 视频 | **另做分镜**：每段说明视觉出现什么、旁白解释什么、何时留预测停顿／揭示差异。画面展示状态、方向和变化，voice 说明“为什么”并连接上一幕，字幕提供可读同步；不是把卡片全文朗读，也不把幻灯片机械拼接。当前仍是静态场景卡片＋短转场，不宣称新增逐镜动画 |

先做最易出错的代表性 pilot 截图／静帧，按 [检查—修订闭环](quality-loop.md) 观察颜色编码、delta、关系、焦点、可读性和媒介适配；不要只确认字段存在。若通用模板无法表达选定关系，回到设计或修授权范围内的通用实现再生成，不能手改最终 HTML／PPTX；不支持的能力明确报告。

## 先确认能力和格式

运行 `doctor` 核对基础能力；需要媒体时运行 `doctor --media`，核对实际工具与缺失项。普通 `doctor` 不探测媒体环境。不自动安装依赖，不悄悄换交付格式。使用已安装的 Edge／Chrome 和 FFmpeg，不默认下载浏览器。基础 HTML 需要 Node.js 22+ 构建；观看离线产物不需要 Node、开发服务器或 CDN。其他格式的可选依赖按能力结果处理。

可通过宿主环境指定已安装工具，不把这些变量当下载或安装指令：

| 配置 | 用途 |
| --- | --- |
| `AHA_BROWSER_EXECUTABLE` | 本地 Edge／Chrome 可执行文件路径 |
| `AHA_BROWSER_CHANNEL` | 已安装浏览器 channel：`msedge` 或 `chrome` |
| `AHA_FFMPEG`／`AHA_FFPROBE` | 本地 FFmpeg／ffprobe 可执行文件路径 |
| `AHA_PYTHON` | 已安装 Python 的可执行文件路径 |

Python 按 `AHA_PYTHON` → 已激活环境 `VIRTUAL_ENV` → **当前命令工作目录**已有的 `.venv-media` → PATH 上的 `python` 选择。虚拟环境在 Windows 下使用 `Scripts\python.exe`，其他平台使用 `bin/python`。不搜索祖先目录／用户主目录，不从 Skill 安装位置推断作品工作目录；显式配置失效不悄悄回退，空 `AHA_PYTHON` 直接报配置错误。复用已有环境，不以探测为由重装软件；从其他目录调用时，可激活已获准环境或使用 `AHA_PYTHON` 指向其绝对可执行文件路径。

`doctor --media` 在 `pythonRuntime.executable`／`source` 报告选择结果，来源分别为 `override`、`active-venv`、`project-venv`、`path`。它只做本地浏览器、FFmpeg／ffprobe 和 Python 中 `edge-tts==7.2.8` 的精确版本探测，不联网合成、不安装依赖。检查 `mediaReadiness` 的各项；缺少任一前提时状态为 `degraded`，不能把退出码成功当作全部媒体能力就绪。所有本地探测通过仍不代表在线服务可用、旁白获批或人工听审通过。

完整发布物在每份 Skill 的 `node_modules` 内携带 `playwright-core`，PPTX 的 JS 库也随发布物提供，因此基础使用无需另跑 `npm install`；这不等于发布目录没有 `node_modules`。PNG 仍需已安装的浏览器，随包的 JS 库不等于已安装浏览器。

随附 `requirements-media.txt` 固定 `edge-tts==7.2.8`；Aha 只提供自己编写的 Python API 适配器与版本 pin，不分发该 Python 客户端库。依赖缺失时由用户明确安装，不由 Skill 自动安装或联网。该版本只有 `src/edge_tts/srt_composer.py` 为 MIT，其余客户端代码为 LGPLv3；用户另行安装的发行包和许可证应分别审查。设置工具路径不改变旁白审批和网络授权门槛。

| 用户选择 | 命令 | 表达方式与验收 |
| --- | --- | --- |
| 可探索 HTML | `render-lab <pack.aha> <新.html>` | 先解释与理解练习，再探索参数／步骤或查来源；检查交互与自然语言条件 |
| HTML slides | `render-slides <pack.aha> <新.html>` | 同一事实的线性讲解；检查导航、备注与来源 |
| 图片卡片预览 | `render-card <pack.aha> <新.html>` | 聚焦直接解释、概念图示或保存的模型状态、答案及必要条件，不截整页 Lab |
| PNG 图片 | `render-image <pack.aha> <新.png>` | 本地已安装 Chrome／Edge 截取专用卡片；检查中文、裁切与清晰度 |
| 原生可编辑 PPTX | `render-pptx <pack.aha> <新.pptx>` | 从 Pack 状态适配文本与原生形状；不把整页截图塞进 PPT 冒充可编辑 |
| 语音视频 | 以下计划／审批／音频／渲染链 | 本地浏览器与 FFmpeg；TTS 是另行选择和授权的网络步骤 |

所有输出使用新路径，放在 Pack 外。图片／PPT 不是运行原仓库的截图或观察轨迹。保留同一 Claim、数值、单位、来源性质和必要限定，少字不等于少事实。

若流程含探索导入，主 HTML、卡片／PNG、原生 PPTX 都使用实际导入的 Pack；核对产物与回执的 Pack 身份，不退回源 Pack 渲染再声称导入已验证。待审阅视频计划也须绑定最终选定修订，不能移用身份不匹配的既有音频。

## 视频：先展示只读计划，再确认

1. `prepare-video <pack.aha> <新-plan.json>` 生成待审阅计划。它不合成音频、不渲染 MP4、不代表已经批准。
2. **将计划关联的提纲、逐段完整旁白、字幕／画面对应关系、provider／voice／rate、时间安排与时长策略、当前 `planHash` 展示给人审阅**，不能只给文件路径或哈希让用户盲签。这是给委托人的审批材料，不是视频正文或旁白。`prepare-video`／`video-plan-check` 返回的 JSON 包含 `provider`、当前 `planHash` 和含完整旁白的 `plan`；不要给计划文件添加 Schema 外的同名字段。默认 `voice: "zh-CN-XiaoxiaoNeural"`、`rate: "+0%"`、时长范围 60–90 秒；这只是待审阅计划，不是授权或实测时长。每句最多 84 字符，最多 40 段；超限先改草案／叙事，不静默截断。
3. 用户明确批准当前旁白版本及其外发；`planHash` 绑定计划文本、voice、rate 和时长策略。**任何计划编辑后都运行 `video-plan-check <pack.aha> <plan.json>`**，自动重新计算身份，展示完整新版本，再取得当前哈希的批准及网络授权；没有另外的 sealing／封存命令，也不手改哈希。用户已经明确选择 Edge TTS 时保留该选择，不重复询问，但它不是对未来旁白版本的 blanket consent。提供方改变还需单独确认，不能用相同计划哈希冒称已经批准另一提供方。
4. 若用户选择 Edge TTS 且明确允许外发，才调用：

   ```text
   synthesize <pack.aha> <plan.json> <新-audio-dir> --approve <planHash> --allow-network
   ```

   不默认上传私有材料。只向已确认提供方发送已确认的旁白文本，不发送完整 Pack、源码、检索日志或凭据。回执记录 provider、voice、哈希与实际结果，不写密钥／token。
5. 核对实际获得的音频时长、分段和可懂度，再使用获准音频：

   ```text
   render-video <pack.aha> <plan.json> <audio-dir> <新.mp4> --approve <planHash>
   ```

   需要已安装的 Chrome／Edge 和 FFmpeg，Edge TTS 链还需已安装的 Python／可选依赖及网络授权。缺失则停止并报告，不能声称后台安装或合成成功。
6. 时间线以实际音频测量为准，不从字数猜时长或用固定停留时间冒充音画同步。实测总时长不在批准范围时拒绝输出，不拉伸／压缩语音来凑时长；修改内容或时长策略后重新 `video-plan-check` 并审阅批准。先按下文审阅 pilot，再检查正式 MP4 的画面、字幕、可懂度、同步、音量与结尾；浏览器截图和编码成功不能代替观看／试听。不能执行的检查明确标未执行。

用户提供音频时按随附 `provided-audio.schema.json` 准备 `audio-files.json`，使用 `import-audio <pack.aha> <plan.json> <audio-files.json> <新-audio-dir> --approve <planHash>`。这是明确标记 `provider: "provided-audio"` 的离线替代，不是 Edge TTS 成功或离线版 Edge；不得隐瞒提供方切换。人工核听音频与批准文本一致，导入成功不证明旁白内容一致；不为绕过审批伪造 manifest，不承诺未实现的其他 TTS 集成。Edge TTS 是 Microsoft 在线语音的社区客户端，不是离线语音或 Azure 身份服务，不承诺提供 Azure 凭据。在线服务条款、可用性、声线许可和隐私约束与本地客户端代码许可不同，需要分别审查；客户端可安装不等于在线服务必然可用。

### 实际视频交付规格

输出为 1280×720、30 fps、H.264 视频加 AAC 音频的 MP4，配套逐句烧录字幕、SRT 和实际回执；使用 CLI 返回的产物路径交付。画面是从 Pack 的讲解图示或保存的模型状态适配的原创静态卡片，加短淡入淡出，不是完整 Remotion 级逐镜动画、任意机制的动态演示或原系统运行录像。字幕、画面与旁白沿用相同事实、单位和来源边界。

### Pilot 与正式版分开验收

先制作代表性短片，检查中文、状态展示、来源／限制、字幕与实际配音，再投入正式版。当前没有独立 `pilot` 命令：在新路径创建符合随附 VideoPlan Schema 的小样计划，引用原 Pack 中真实的 slide／Claim，选择少量代表段落及合法时长范围，用 `video-plan-check` 获得当前哈希后，走同一审批、音频和 `render-video` 流程。

小样和正式版是各自的计划身份；不能直接改哈希或重用不匹配的音频 manifest。批准小样不等于批准完整版旁白外发，正式版仍按当前内容单独审批。若环境只能检查静帧和试听，明确“pilot 视频未制作／未观看”，不能将静态卡片称为视频验收。

## 共用质量门槛

- 内容审阅：同一 Pack 的所有格式保留事实、单位、来源和不确定性；`brief.explanation` 的 takeaway、术语、类比边界、visual、conditions、理解题与 answer 及 Slide 图示不得变成新事实。检查图示是否真正解释主题、答案是否讲清理由，而非只检查字段存在。
- 读者审阅：无需制作说明也能理解；可见画面／正文／旁白无受众标签、来源计数、Claim ID／哈希和生产指令，来源入口从属于主题讲解。保留自然语言条件，不用删免责声明的方式隐瞒未知。
- 视觉审阅：标题层级、中文换行、留白、长来源、投屏／窄屏、色彩对比；用实际输出而非开发页面。PPTX 还检查文字和形状确实可编辑。
- 交互审阅：在实际 HTML 操作讲解选择器、次级来源选择器与显式浏览器下载，核对导出记录及导入修订；不能用 CLI 导出替代浏览器下载验收。页面、图片成功不代表所有 PPTX 布局通过，未完成格式分别报告。
- 研究日志、原生 PPTX 审计备注、Pack 讲解备注和内嵌数据可能随文件交付；分享前检查整体，不能因为审计备注不送入 TTS 就认为它们不在文件中。`private` 标签不是加密，不自动上传。
- 同一问题两次局部修补仍失败就返回设计层，不设任意全局通过轮数；依闭环修订到阻塞项关闭或报告真实限制。保留上一有效产物／回执于工作或归档目录，生成物／来源记录／迭代／截图／日志默认放忽略的 artifacts 或获准会话目录；用户指定的交付目录只留一套显式 promotion 的当前成品，不堆积历史版本。
- 向委托人的完成报告与知识成品分开：结构、实际视觉／试听检查、学习任务实际回答与成绩、未测项分别记录。独立 Agent 视觉审阅只是启发式，不是人类理解测试；不编造人类反馈，不将机器回执写成人工验收，也不宣称自动语义审计或宿主冷安装已通过。
